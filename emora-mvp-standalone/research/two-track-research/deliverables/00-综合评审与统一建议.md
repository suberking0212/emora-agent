## 1. 执行摘要

两份课题从两个正交维度审视同一个问题：**如何让 Emora 更专业、更可靠地提供情感支持。**

- **课题 A（专业知识）** 问的是「知不知道怎么安慰」——答案是：把 **Rogers 底座 + MI(OARS) 技法**工程化进结构化 prompt，并用 MITI/MISC-2 派生的 rubric 量化。
- **课题 B（原生能力）** 问的是「模型本身能出多少力」——答案是：**别指望换更新模型**（共情代际无差异），而要用本确定性接口（strict json_schema + reasoning_effort），并兜住「建议安全性下降 + 表演式共情」两个原生风险。

两份课题的结论**高度收敛**：真正的提升来自「**确定性工程（prompt + schema + 评测）**」，而非「更大的模型或更多外部组件」。

---

## 2. 双课题的关系与交叉点

| 交叉点 | 课题 A 视角 | 课题 B 视角 | 统一结论 |
|---|---|---|---|
| 共情无法靠换模型提升 | 需专业知识工程化 | 三代模型共情无差异（arXiv 2603.09997） | 靠 prompt + 评测，不靠换代 |
| 建议安全性 | MI 明确「不诊断、不强迫改变」 | 原生建议安全性代际下降 | 双门禁 + 方法边界共同兜底 |
| 冗长/表演式共情 | 反映性倾听要求简洁 | 推理模型「复杂度惩罚」（ICDH 2026） | 评测加入「简洁性」维度 |
| 结构化输出 | 结果要能进 rubric | strict json_schema 提升通过率 | 原生 schema 是评测的「数据质量底座」 |

## 3. 统一技术建议（MVP 唯一组合）

| 方向 | 建议 | 变更类型 |
|---|---|---|
| 专业方法 | Rogers 底座 + MI-OARS 分层 prompt；CBT 重框作可选技能 | 核心新增（零依赖） |
| 评测 | DeepEval（pytest 原生）+ MI 忠诚度 rubric + 简洁性 rubric + 安全路由回归 | 核心新增 |
| 结构化输出 | 补 `response_format=json_schema strict` | 小改动 |
| 推理深度 | 深思考试点 `reasoning.effort=high` | 小改动（试点） |
| 安全护栏 | 维持 Qwen3Guard-Gen；以 AILuminate(Practice) 为外部验收标准 | 维持 + 新增评测标准 |
| Agent 框架 | 维持 LangGraph 1.2.18 | 不变 |
| RAG / 工具 / 微调 | 不引入 | 非目标 |

## 4. 三项必须贯彻的「否决性事实」

1. **不换模型提升共情**：arXiv 2603.09997（共情 H=4.33 p=0.115）——任何「升级到 GPT-6 会更好」的假设都不成立。
2. **原生能力的反噬必须兜底**：建议安全性下降（H=16.63 p<0.001）+ 表演式共情（ICDH 2026）——评测与门禁不是可选项。
3. **第三方中转不可作事实依据**：`ruoli.dev` 上游路由无公开资料，本调研不采信其行为结论；原生能力（reasoning/structured outputs）经第三方中转是否透传**不可验证**。

## 5. 实施路线（阶段化）

### 阶段 0（本周，零依赖）
- 分层 prompt：Rogers 底座 + MI-OARS（改 `backend/prompts/system.md` 文案，不动架构）。
- 建立 MI 忠诚度 rubric + 20–30 条中文金标集。

### 阶段 1（评测闭环）
- DeepEval 接入 `backend/tests/`（pytest 原生），落自定义 metric：MI 忠诚度、简洁性、安全路由。
- A/B：现状 prompt vs MI 增强 prompt。

### 阶段 2（原生能力）
- `backend/provider.py` 补 strict json_schema（核对 required 全覆盖）。
- 深思考试点 reasoning_effort=high + 冗长度回归。

### 阶段 3（仅在有数据后）
- 重新评估是否微调（LLaMA-Factory）——当前**不启动**。

## 6. 风险清单

| 风险 | 缓解 |
|---|---|
| MI 反映性倾听被模型「表演式共情」污染 | 简洁性 rubric + 人工抽检 |
| 原生建议安全性下降 | Qwen3Guard 输出门禁（现有）+ AILuminate 回归 |
| strict json_schema 与现有 schema 不兼容 | 逐字段核对 required，保持 Pydantic 兜底 |
| 中文 MI 量表适配不足 | 用简化 rubric，先金标集后量表 |

---

## 7. 结论

Emora 的专业能力提升，**不靠更大的模型、不靠新框架、不靠训练数据**，而靠三条确定性工程：**(1) 把 Rogers+MI 写进 prompt；(2) 补原生结构化输出与可调推理深度；(3) 用 DeepEval + 专属 rubric + 安全门禁建立可回归的评测闭环。** 对此，两份课题的证据一致、可追溯、可复现。
