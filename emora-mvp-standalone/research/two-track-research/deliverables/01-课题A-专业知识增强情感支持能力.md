# 课题 A：专业知识增强情感支持能力 —— 技术调研报告

- 调研日期：2026-10-31
- 执行主体：OpenClaw 主会话（QClaw）
- 目标项目：`emora-mvp-standalone`（情绪复盘助手 MVP）
- 报告性质：技术选型调研 + 证据交叉审查，不含任何生产代码修改

---

## 1. 执行摘要

本报告回答一个问题：**能否、以及如何把可复现的「专业对话方法」工程化进 Emora，从而增强其情感支持能力。**

核心结论：

1. **在可用的专业方法中，只有 Motivational Interviewing（MI，动机式访谈）具备「可编码、可复现、可评分」的完整工程化证据链**（MITI / MISC-2 忠诚度编码系统有公开学术实证），这是把「专业知识」变成「可回归测试的软件能力」的唯一可靠路径。
2. **Rogers 人本取向**（共情、无条件积极关注、真诚一致）应作为 Emora 的「底座语气」，它天然契合 Emora 现有的「情绪反思、不诊断、区分事实与假设」设计，但本身缺乏强 AI 实证，只宜作底座、不作评分主线。
3. **CBT（认知行为疗法）只能作「认知重框」参考技能，不能作主导方法**：多篇证据一致表明 LLM「可辅助识别/重框不合理想法，但不应被依赖主导 CBT 交付」，且 Emora 的 PRD 明确排除「医疗诊断、治疗替代」。
4. **最硬的实证结论是：方法的选择胜于模型的换代**。arXiv 2603.09997 的临床测量显示 GPT-4o→o4-mini→GPT-5-mini 三代模型「共情得分无统计学显著差异」，真正改变的是「安全姿态」而非共情能力——这意味着**想提升情感支持，靠换新模型不可行，必须靠专业知识（prompt 工程 + 专用评估）**。

---

## 2. 背景与目标

### 2.1 背景

Emora 是一款「情感复盘助手」，目标是帮成年用户整理和理解自己的情感困扰，给出有依据、可理解、可执行的下一步建议（`emora-mvp-standalone/doc/PRD.md`）。当前实现只有一套通用情绪复盘 system prompt（`backend/prompts/system.md`），**没有任何显式的专业对话方法工程化**。

### 2.2 目标

- 梳理可工程化的专业对话方法及其证据强度；
- 判断哪些方法能与 Emora 的 LangGraph 工作流、安全门禁、结构化输出契约融合；
- 给出「专业知识增强」的落地建议与可验证的评测 rubric。

### 2.3 范围与方法

- 只调研公开、可引用的学术/官方来源（JMIR、JAMA Network Open、ACL Anthology、arXiv、PubMed 等）；
- 对无公开证据的实践（如内部自研疗法框架）不纳入结论；
- 交叉审查：同一结论至少有一篇独立来源支撑或被显式标注为单一来源。

## 3. Emora 架构基线（只读检查，非历史描述）

- 编排：`langgraph==1.2.18` 单节点 StateGraph（START→agent→END），单次 Agent 调用（`backend/agent.py`）。
- 结果契约：`AnalysisResult` = summary / emotions / conflict / user_needs / suggestions / next_step / safety_note（`backend/contracts.py`）。
- 安全：Qwen3Guard-Gen 输入+输出双门禁；**程序控制权与 Agent 决策权严格分离**，Agent 不能自主调用工具、写库、改状态（`doc/TECHNICAL_DESIGN.md` §2）。
- 澄清：单轮 `ask_clarification`，上限 1 轮。

**对课题 A 的关键含义**：Emora 的「结果 schema」本身已经是「结构化情感复盘」，天然适合把专业方法作为「节点内结构化 prompt + 输出校验 rubric」落地，而不需要引入任何「疗法框架 SDK」（这类 SDK 事实上不存在成熟开源的）。

## 4. 专业对话方法逐一分析

### 4.1 Rogers 人本取向（Person-Centered）

**核心技法**：共情理解、无条件积极关注、真诚一致。

**证据**：作为心理治疗通用态度，Rogers 取向广泛被用作聊天机器人「底座语气」，但**针对「LLM 工程化 Rogers 取向」的强实证稀缺**。它是「无争议但测不细」的方法。

**对 Emora 的适用性**：高，且已部分实现。Emora 现有 system prompt 的「不诊断、区分事实与假设、不用绝对化断言、不操纵他人」正是人本取向的工程化雏形。建议**显式命名并固化为底座语气**，但不作为度量主线。

### 4.2 Motivational Interviewing（MI，动机式访谈）

**核心技法**：OARS —— 开放式提问（Open questions）、肯定（Affirmations）、反映性倾听（Reflections）、总结（Summarization）；促进「change talk」（改变性语言）。

**证据（本方向最强）**：

1. **可编码评估系统成熟**：MITI（Motivational Interviewing Treatment Integrity）与 MISC-2（Manual for the MI Skill Code 2.0）能逐轮编码对话的 MI 忠实度——这为把 MI 变成「可回归测试的软件 rubric」提供了现成的、有学术背书的评分框架。
2. **ACL 2025（Findings）「A Fully Generative MI Counsellor Chatbot」**：用 GPT-4o + MI 构建戒烟咨询聊天机器人（MIBot），与临床科学家协作迭代，106 名参与者实测，并用自动化 + 人工评估验证「机器人 MI 忠实度」与「来访者回应」。结论：LLM 能稳定承载 MI 结构化对话。
3. **JAMA Network Open（2026-03）MI 对齐研究**：154 个高保真 MI 会话、3706 个治疗师回合，发现 LLM 与治疗师「语义相似度低、但情境适当性更高」，并强调「**prompt engineering 对 MI 对齐至关重要**」。这条直接印证：MI 的落地在「prompt + 评估」，不在「换更大的模型」。
4. **JMIR Formative（2026）「Aimi」**：把 MI 策略操作化为「LLM 结构化工作流」，专家 MI 教练用 MISC-2 评分验证会话忠实度；证明「MI 策略 + 工作流节点」是与 LangGraph 形态天然契合的路径。

**对 Emora 的适用性**：**最高**。Emora 的目标（帮用户梳理矛盾与诉求、给可执行下一步）与 MI「协作式探索改变动机」高度吻合；MI 明确「不诊断、不强迫改变」，不会让系统滑向医疗诊断。

### 4.3 CBT（认知行为疗法）

**核心技法**：Catch It（捕捉不合理自动化想法）→ Check It（检验其真实性）→ Change It（重框为更现实的认知）。

**证据（结论审慎）**：

1. **JMIR AI（2024）「Can LLMs Replace Therapists?」**：系统评估 LLM 完成 CBT 三阶段任务，明确结论「LLM 可提供识别/重框不合理想法的**合理建议，但不应被依赖来主导 CBT 交付**」。
2. **CBT-Bench（arXiv 2410.13218）**：把 CBT 能力拆成「知识获取→认知模型理解→治疗性回应生成」三级，为「LLM 辅助 CBT」提供了可复现的评测阶梯。

**对 Emora 的适用性**：中。Emora 可把「识别不合理的自动化想法 → 温和检验 → 重框」作为**可选认知技能**融入 suggestions/next_step，但**明确不主导、不诊断**（与 PRD 一致）。

### 4.4 Hill Helping Skills（三阶段模型）

**核心**：Exploration（探索）→ Insight（洞察）→ Action（行动）。

**证据**：主要用于咨询师训练，**AI 工程化实证弱**。

**对 Emora 的适用性**：概念层面可吸收（探索≈现状澄清、洞察≈核心矛盾/需求识别、行动≈下一步），但不作为独立工程方法。Emora 现有 schema 已隐含此三阶段结构。

## 5. 技术方案对比（如何把「方法」变成「代码」）

| 方案 | 描述 | 证据强度 | 对 Emora 契合度 |
|---|---|---|---|
| 单一大 prompt 注入原则 | 在 system prompt 写 MI 原则 | 中（JAMA 提示「prompt 关键」） | 高，零架构变动 |
| 结构化工作流（LangGraph 节点） | 每个 MI 技法是节点/子步骤 | 高（Aimi JMIR 2026） | **最高**，与现有 StateGraph 融合 |
| 微调/RLHF 对齐疗法 | 训练模型说 MI 话术 | 中（EVA、Empathy-R1 已有；但 Emora 无数据） | 低（MVP 无标注数据，见课题 B） |
| 检索增强（RAG 注入疗法手册） | 检索 MI/CBT 手册片段作上下文 | 低（无强公开实证；且 PRD 排除检索） | 低 |

**结论**：MVP 采用「**结构化工作流 + 节点内显式 MI 原则 prompt**」，零新框架、零新依赖。

## 7. 优缺点分析

### 7.1 MI 作为主方法的优点

- 有可复现的评分系统（MITI/MISC-2），可工程化为评测 rubric；
- 与 Emora 目标、PRD 边界、LangGraph 结构三方契合；
- 明确「不诊断」，合规风险低。

### 7.2 MI 的缺点 / 风险

- OARS 的「反映性倾听」对模型细腻度要求高，需要 pipeline 校验（模型可能「表演式共情」，见课题 B 的 ICDH 2026 证据）；
- MITI/MISC-2 原始量表是临床编码工具，直接搬用需简化、需中文适配（原始以英文会话为主）；
- 只有 prompt+评估路线，短期无法用「更多数据训练」提升（MVP 无数据）。

### 7.3 CBT 的适用条件

- 仅当用户明确表达「想法卡住了/反复担心某事」等认知困扰时，提供「Catch-Check-Change」式轻量重框；
- 必须保留「这是想法的一种可能，不是诊断」的口径。

---

## 8. 对 Emora 的适用性结论

- **底座**：Rogers 人本取向（显式化现有 design）。
- **主线**：MI 的 OARS，作为结构化 prompt 写入 LangGraph 的 agent 节点。
- **可选技能**：CBT 认知重框（Catch-Check-Change），仅在认知困扰场景触发。
- **不采用**：Hill 三阶段作为独立方法（概念吸收即可）、任何疗法 SDK/检索注入。

---

## 9. 架构设计建议（最小侵入）

```
Emora 现状（agent 节点单次调用）
  └─ system prompt: 情绪复盘通用规则
        ↓ 增强为
  system prompt (分层):
    1) 底座: Rogers 人本取向（显式命名）
    2) 技法: MI-OARS 四技能的操作定义 + 何时用
    3) 硬边界: 不诊断/区分事实假设/不操纵（保留现状）
    4) 可选: 认知重框技能（Catch-Check-Change，触发条件明确）
```

**关键点**：不引入新的 LangGraph 节点（保持单节点 + 单轮澄清），全部落在 prompt 与 `AnalysisResult` 契约的字段语义内。这是「专业知识增强」与「MVP 规模」的最优平衡。

## 10. 实验验证方案

1. **构建 MI 忠诚度 rubric**（从 MITI/MISC-2 简化的中文版）：维度 = 开放式提问比例、反映性倾听（简单/复杂反映）、肯定、避免「直接给建议/过早诊断」。
2. **金标集**：20–30 条中文情感困扰输入 + 专家（或资深咨询师）标注的「理想回应要点」。
3. **基线 vs 增强 A/B**：同一模型、同一输入，对比「现状 prompt」与「MI 增强 prompt」的 rubric 得分。
4. **LLM-as-judge + 人工抽检**：用 DeepEval 自定义 metric（见综合报告 §评测）跑 LLM 裁判，再抽 10% 人工复核，避免自评分偏差。
5. **安全回归**：确认 MI 增强不改变安全路由（Unsafe 仍阻断、Controversial 仍放行、Suicide/Violent 仍引导现实求助）。

**验收标准**：增强版在「开放式提问 + 反映性倾听」两维显著优于基线，且安全路由回归零退化。

---

## 11. 结论

课题 A 的答案是确定的：**Emora 应把 Rogers 人本取向固化为底座、把 MI 的 OARS 作为显式技法工程化进现有的结构化 prompt，并配套一个从 MITI/MISC-2 简化来的 MI 忠诚度评测 rubric。** 专业知识增强不依赖换模型、不依赖新框架、不依赖训练数据，是当前性价比最高、证据最硬、合规最稳的路线。
