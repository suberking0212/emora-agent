# 04 · 跨案例专业行为与隐性知识分析

- 研究日期：2026-10-31
- 输入：`03-case-database.jsonl`（20 条） + `02-source-catalog.md`（A/B/C/D 来源）
- 输出：**条件化决策规则**（`条件 → 判断 → 行为`），而非固定步骤清单。
- 标注约定：`[事实]` `[研究结论]` `[专家经验]` `[推断]`；证据等级随附。

---

## 0. 分析单位与编码方法

不是"逐案例总结"，而是对三个层次编码：

1. **决策分叉点（decision fork）**：同一情境下从业者面前有多种可选动作。
2. **关键线索（cue）**：触发某选择的信息信号。
3. **条件（condition）**：决定"此行为适用于此、不适用于彼"的边界。

从 20 条案例中识别出 **7 个反复出现的专业行为模式**，每条都落到"什么时候做 / 怎么做 / 为什么 / 得到不同反馈后怎么变"。

## 1. 行为模式一：先反映（reflect）后提问（question），且反映多于提问

**证据**：S01/S03（MI，反射:提问比高预测好结果 [研究结论 A]）；S04（≥50% 应为 complex reflection [研究结论 A]）；C003（Mohammed 情绪反映）；C002（咨询师自批注"我应反映而非继续提问" [专家经验 B]）；C006（五级共情 L3+ 才达标 [专家经验 B]）。

**条件化规则**：
- **什么时候反映而非提问**：
  - 用户在表达强烈情绪（创伤、坏消息、崩溃、愤怒）时 → 先反映情绪，把"被听懂"还给用户（C003/C006）。
  - 用户说的是"感受/体验"，而非"事实/信息"时 → 反映其意义，而非追问细节。
  - 你已有 70% 以上的把握理解了用户 → 用反映来"确认理解"，比用问题更省力、更少打断（S07：用 reflection 澄清而非 question）。
- **什么时候必须提问**：
  - 理解不足（歧义指代、关键背景缺失）→ 澄清性提问（S07："him 指丈夫还是父亲"）。
  - 风险情境需要具体事实（有没有计划/手段/何时何地）→ 封闭式精确提问（S26/S27，安全评估 [权威 A]）。
  - 用户明确要求分析、或处于认知探索阶段 → 开放引导性问题（C005 考试焦虑）。
- **反问自己**（S07）：这个问题是为"澄清我的理解"还是"帮用户探索自身"？两者都不服务时，不提问。

**反馈后的行为变化**：反映后若用户说"不是这样/你理解错了"→ 接受，重新假设（S01："Be open to being wrong, use feedback to make another hypothesis" [研究结论 A]）。这是"判断可修正性"的直接体现。

## 2. 行为模式二：把"决定权"还给用户，不争辩、不劝服

**证据**：S01（"It's really up to you" [权威 A]）；S03（"避免争论、不强推己见是正确立场" [权威 A]）；S09（"咨询师不给出建议，而是呈现选项" [专家经验]）；C001（直接示范）。

**条件化规则**：
- **当用户表达阻抗/矛盾（ambivalence）、否认、'你说得对但是…'时** → 不争辩。争辩会激活 reactance，让用户更固守原立场（S04 引 reactance theory）。
- 转而：① 命名矛盾本身（"一方面…另一方面…"，S03 总结句式）；② 把决定权交还（"最终决定在你"）。
- **例外**：这不是"永远不给建议"——见模式六。

---

## 3. 行为模式三：聚焦"互动模式/过程"，而非"内容对错"

**证据**：C004/C012（董娜复盘："伴侣治疗聚焦互动模式而非吵架内容" [专家经验 C]）；S17（EFT 追踪负向互动循环 [研究结论 A]）；S36（Gottman 四骑士是"模式"分类 [研究结论 A]）。

**条件化规则**：
- **当关系冲突内容多变但模式恒定**（每次都为洗碗/钱/育儿吵，但"一人吼—一人沉默走开"的模式不变）→ 放弃"这次到底谁对"，转向"你们是怎么吵的、这个循环怎么一步步升级"。
- 具体做法：把指责翻译成"I 听到你说…你感受到的是…"（C002），把"你为什么这样对我"翻译成"当对方这样做时，你的身体/情绪感觉到什么"（S16 EFT 情绪引导 [专家经验 A]）。
- 为什么：内容争不赢（双方都有理），模式才是可改变的对象。

---

## 4. 行为模式四：情绪先于认知——先稳定化，再处理问题

**证据**：S38/S39（grounding、window of tolerance [权威/专业]）；C006（先命名情绪再谈方案）；S25–S29（危机时先安全再谈话 [权威 A]）。

**条件化规则**：
- **当用户处于情绪唤起（flooded/panic/崩溃/愤怒失控）时** → 不分析、不建议、不辩论。先帮助"回到当下"（grounding、命名情绪、放慢呼吸）。
- 原理：情绪唤起会关闭认知加工与创造性问题解决能力（S39 window of tolerance；S34 Stonewalling 的生理 flooded [研究结论 A]）。
- **阶梯**：情绪严重失调且出现即时危险信号 → 直接进入安全处理/转介（见模式七），而非 grounding。
- Emora 可迁移项：识别"情绪唤起"这一信号本身，先于任何分析栏目的输出。

---

## 5. 行为模式五：先觉察再改变——不跳步给建议

**证据**：C010（小雅前 8 次先做"觉察记录"）[案例 C]；C015（强迫性重复：先觉察模式）；C011（自体心理：先巩固联盟再触碰创伤）[研究结论 B]。

**条件化规则**：
- **当用户的问题是"长期行为模式/自动化反应"（讨好、冲动、回避）而非"一次性决策"时** → 不给"你应该直接拒绝"这类建议，因为自动化反应不经大脑（C010：80% 讨好未经大脑 [案例 C]）。
- 先让用户"看见"模式：何时发生、触发什么、脑子里第一反应是什么。
- **当用户明说"我准备好了，告诉我怎么做"且问题是一次性、情境性的** → 才可给可执行建议（见模式六）。

---

## 6. 行为模式六：建议不是"告诉该做什么"，而是"呈现选项+可执行下一步"

**证据**：S09（Egan："if I were in your situation, here are a few options I might look into" [专家经验]）；S10（先求许可"would it be okay if I shared"，挑战后"check how it landed" [专家经验]）；S03（goal 设定是 client-driven [权威 A]）。

**条件化规则**：
- **给建议的触发条件**：
  - 用户明确要求解决方案；且
  - 问题是一次性/情境性/可操作（而非需深层觉察的模式）；且
  - 用户情绪已稳定（非唤起态）。
- **给建议的方式**：选项式、带"这是我可能会考虑的选项"预留自主；不给命令（"你必须"）。
- **给建议后**：check 落地感受（"这怎么落在你身上？"），据反馈调整——这就是"反馈适应"。

---

## 7. 行为模式七：识别危险信号，从"分析"切换为"安全处理/转介"

**证据**：S26（SAFE-T 五步 [权威 A]）、S27（ASQ "do you need help to keep yourself safe" + 即时风险→急诊 [权威 A]）；S15（Socratic 不适用于危机/无选择环境 [权威 A]）；S40（国人卫指南：有明显自杀倾向/严重思维障碍者不适合认知治疗 [权威 A]）。

**条件化规则（这是最重要的一条安全决策）**：
- **触发从"继续分析"切换到"安全处理"的信号**：
  - 自杀意念 + 计划（何时何地）+ 手段（如何）+ 意图（是否要做）四项中的意图/计划出现 [权威 A, S26/S27]。
  - 自伤、伤害他人的即时风险。
  - 明确的精神病性症状（幻听命令、严重妄想）。
  - 高唤起且无法自我稳定（不是"低落"，是"失控"）。
- **切换后的动作**：不再做情绪复盘/认知重框/建议，改为：直接询问安全（S27 用封闭式精确问）；给危机资源（紧急联系方式/热线）；建议立即就医或联系支持网络；必要时联系紧急接触人（S25 安全计划与家庭联动）。
- **Emora 边界**：Emora 无医疗/危机处置能力，必须能识别这些信号并**转介**，且这在当前 Qwen3Guard 输出里没有对应字段（项目已记录的技术债，见 professional-capability README §2.2）。

## 8. 隐性知识的四个高频模式（跨案例归纳，`[推断]`）

以下判断在多个案例中反复出现，但无单一来源直接陈述，标记为跨案例归纳：

1. **[推断] 表面诉求 vs 真实困扰的差异信号**：
   - 用户反复问"怎么办/技巧"（如何习惯沉默、如何让他回心转意、如何拒绝），但真正的内容却是关系焦虑、价值感、恐惧被弃——信号是：**问题里几乎没有关于"自己感受"的陈述，全是"对方/环境"**（C007/C008/C010）。此时真实需求是"被理解/安全感"，不是方案。
2. **[推断] "是否准备好接受建议"的信号**：用户若仍在"描述痛苦、归因外化、情绪唤起"状态 → 未准备好；用户若开始"我能做什么/下一步/具体情境" → 已准备好。判断依据是 change talk 是否出现（S01 "change talk" 概念 [研究结论 A]）。
3. **[推断] 发现自己判断错误的信号与修正**：用户以"不是/你没懂/其实"开启反驳、或对反映无回应（沉默）、或话题反复绕开某点 → 可能判断有偏；修正动作 = 退回到反映+重新假设（S01），而非坚持原解读。
4. **[推断] 何时停止分析转向"陪伴"**：用户说"我只是想说说话"、或明确拒绝被分析、或在哀伤/重大丧失中 → 停止分析、进入纯陪伴（倾听+在场+反映），把"分析"降为可选项。

## 9. 常见判断错误及其纠正（跨案例）

| 常见错误 | 证据来源 | 纠正方向 |
|---|---|---|
| 反复追问导致"审讯感"（questioning 过多） | S07/S09 | 提高 reflection 比例；问前自查"服务于谁" |
| 把"想避开丈夫/沉默"直接等同于"回避型依恋"诊断 | S21（没有研究支持，把经历质量与依恋模式混淆）[权威 A] | 依恋看"如何沟通"而非"说了什么经历"，避免贴标签 |
| 面对阻抗时道歉（把阻抗误当自己失误） | S30（阻抗致破裂时道歉无效，应敏感探索）[研究结论 A] | 先区分破裂成因：自身失误→道歉+探索；阻抗→探索其议题 |
| 争吵式（disputatious）苏格拉底 | S14 [权威 A] | 问题须配合 reflection/summary，协作而非盘问 |
| 情绪唤起时给建议/讲道理 | C006/C010 | 先稳定化、先觉察，再谈方案 |
| 危机情境仍做认知重框 | S15/S40 | 切换安全处理 |

## 10. 哪些不能直接迁移到 AI Agent（关键边界）

1. **诊断与贴标签**（依恋/人格/障碍分类）→ 不可迁移。Emora 是 IV 层非临床支持（见 01 §2.2）。Agent 只能"描述观察到的模式"（"你提到他总在冲突时消失"），不能"判定他是回避型依恋者"。
2. **身体/微表情/移情的即时处理** → 部分不可迁移。C05（转婚戒微表情）依赖视觉通道与长期关系，文本 Agent 无法等价实现；只能迁移其"关注重复出现的行为线索"这一抽象原则。
3. **危机现场处置（观察患者、直接联系急诊）** → 不可迁移为"执行"，只能迁移为"识别 + 转介话术 + 提供资源"。
4. **治疗性沉默/非言语在场** → 文本媒介无法承载；须转化为"不打断、留出空间、放慢回合"的等价操作，并评估其有效性。
5. **长期移情-反移情的动态管理** → Emora 单次/轻度多轮场景不适用；但其"把过度依赖温和命名并规范化"的底层原则可用于"用户对 AI 产生过度情感依赖"的提示（弱化形式）。

## 11. 条件化决策知识小结（可直接进 05 能力模型）

| 条件（Condition） | 判断（Reasoning） | 行为（Action） |
|---|---|---|
| 强烈情绪/创伤/崩溃 | 认知通道关闭，需要被看见 | 反映情绪 + 稳定化，不分析不建议 |
| 歧义/关键背景缺失 | 理解不足会导向错误假设 | 澄清提问；或反映式澄清 |
| 阻抗/否认/矛盾 | 争辩会强化阻抗 | 命名矛盾、交还决定权 |
| 关系冲突内容多变模式恒定 | 内容争不赢 | 转向互动模式探索 |
| 长期自动化行为模式问题 | 不经大脑，建议无效 | 先觉察模式再谈改变 |
| 一次性情境问题 + 明确求助 + 情绪稳定 | 用户已 ready | 选项式建议 + 可执行下一步 + check 落地 |
| 即时危险信号（计划+意图） | 已超出支持边界 | 停止分析，转介 + 资源 + 直问安全 |
| 只想倾诉/哀伤/拒绝分析 | 需求是陪伴 | 纯粹倾听与在场，退出分析 |
