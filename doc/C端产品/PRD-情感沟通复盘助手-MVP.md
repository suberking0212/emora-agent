# PRD：情感沟通复盘助手（MVP）

- 版本：0.1（讨论稿）
- 日期：2026-10-16
- 阶段：低成本原型与封闭内测
- 项目目标：验证用户是否能从结构化的 AI 沟通复盘中获得明确价值，以及是否愿意为这种价值付费；不以本版本证明规模化市场成立。

## 1. 产品概述

### 一句话描述

用户提交一段经过处理的关系沟通材料和必要背景，获得一份区分事实、解释与推断的复盘，帮助其理解可能的沟通误差，并选择下一步如何表达。

### 首版产品形态

- 面向测试用户提供中文网页体验，支持桌面和移动端浏览器。
- 分析核心保持独立、可在本地命令行运行，便于开发者快速迭代、回放案例和运行评测；CLI 是开发与内部验证入口，网页是首轮用户测试入口。
- 先以邀请制或链接形式进行小范围内测。是否公开投放、在哪些平台投放以及是否接入情感博主渠道，待内测和获客测试后决定。

### 产品定位

这是一个“沟通复盘与下一步表达建议”工具，不是陪伴式虚拟伴侣、心理治疗或关系诊断服务。它不替用户断言对方的真实动机，也不替用户决定是否分手、复合或结婚。

## 2. 用户与待解决问题

### 首轮测试对象与长期用户

首轮从 18 岁及以上学生/开发者群体招募测试样本，以获取第一轮真实使用数据；优先邀请近期确有恋爱或亲密关系困扰、愿意体验并反馈的人。该群体是可触达的早期测试样本，不因此定义为长期目标客群，也不能代表个人用户总体或用于单独估算付费率。后续需根据困境类型、使用行为、复用和价值证据识别长期服务对象。

### 用户问题

- 用户拿到一段聊天后容易反复猜测对方意图，难以区分原话与自己的解读。
- 通用 AI 回答可能迎合提问者、过度推断或给出听起来确定但证据不足的建议。
- 用户需要一个低压力的方式，厘清沟通卡点，并准备一条更清楚、尊重边界的表达。

### 首版核心任务

“我把自己的感情经历和矛盾讲给你听，请理解上下文，帮我分析问题在哪里、我可能做错或忽略了什么、有哪些其他解释，以及我接下来可以怎么处理。”优化建议和决策支持是核心价值。

## 3. 产品目标与非目标

### 目标

1. 用户能在无需注册的情况下完成一次端到端复盘。
2. 输出可读、具体、可执行，并清晰区分材料事实、用户解释和模型推断。
3. 用户能指出报告中有帮助、无依据、遗漏或不安全的部分。
4. 经单独同意的用户可贡献脱敏材料和反馈，用于产品分析与质量改进。
5. 通过小规模内测获得后续“继续、调整或停止”的真实证据。

### 非目标（MVP 不做）

- 长期陪伴、虚拟恋人、角色扮演、拟人化亲密关系或连续聊天型关系服务。
- 挽回、操控、PUA、监视伴侣、诱导对方作决定等功能。
- 精神障碍诊断、心理治疗、婚姻治疗、法律意见或专业咨询替代。
- 对对方是否爱用户、是否出轨、人格类型、依恋类型或关系结局作确定性判定。
- 账号体系、跨会话长期记忆、社交功能、支付系统、公开内容社区、自动触达第三方。
- 将测试样本或报告满意度直接解释为市场规模或商业成功。

## 4. 用户流程与对话方式

1. 用户进入网页，阅读用途、边界、数据处理说明和年龄提示。
2. 用户选择输入方式：粘贴文本、手动描述事件，或上传聊天截图。
3. 页面提醒用户先遮盖姓名、头像、电话号码、账号、地址等身份信息，并尽量取得截图中其他人的适当授权；首版提供脱敏操作指引，不宣称自动脱敏无误。
4. 用户可以直接用自然语言讲述经历、矛盾或问题；页面仅提供可选提示帮助组织信息，不要求先完成长问卷。
5. 用户确认提交材料，并单独选择是否允许将脱敏材料与反馈用于产品改进。默认不勾选；拒绝不影响本次分析。
6. 系统解析文本或图片，展示可识别的材料摘要供用户确认/修正后再分析。解析失败时允许改用文本或手动输入。
7. Agent 先基于已有内容理解和分析；只有缺失信息会实质改变判断或建议时，才简短追问。它可主动引导用户补充关键背景，但不得反复盘问或把体验做成诊疗式逐题问答。
8. Agent 给出针对用户困惑的分析和具体优化建议，可自然开展后续对话；用户补充或纠正后应据此更新判断。适合收束时生成可回看的复盘总结。
9. 高风险内容触发安全回应或停止常规建议。用户可提交可选反馈；离开前可删除本次记录。

## 5. 输入要求

### 支持的输入

- 纯文本聊天记录。
- 用户手动描述的沟通事件。
- 聊天截图图片；通过 OCR/视觉模型提取内容后，必须允许用户检查和修改识别文本。

### 输入限制

- 首版只支持静态图片，不支持音频、视频、社交平台账号授权或自动抓取。
- 限制单次图片数量和文件大小，具体上限由实现与模型成本确定，并在页面明确显示。
- 提示用户仅提交完成分析所需的最少材料；不鼓励上传完整聊天历史、身份证件、医疗记录、财务资料或其他无关敏感信息。
- 不满 18 岁用户不纳入本轮内测。年龄提示不能替代有效的年龄核验或合规设计；是否允许未来未成年人使用须另行评估。

## 6. 输出报告结构

分析可以自然对话呈现，不要求每轮套固定模板；适合总结时，可包含：

1. **问题摘要**：复述用户希望解决的问题，不替用户改变目标。
2. **材料中明确发生的事**：只列有输入依据的内容；尽量标注对应原句或时间点。
3. **用户的感受与解释**：明确注明来自用户自述，不把它们升级成客观事实。
4. **可能的沟通模式 / 多种解释**：至少提供两个合理假设（如果材料足够）；分别说明支持依据、反证或缺失信息，不做对方内心断言。
5. **尚不清楚的地方**：指出会显著影响结论的缺失背景；只在必要时提澄清问题，同时基于当前信息先提供有限分析。
6. **优化建议与下一步**：说明用户自身可调整之处，提供具体、非操控且尊重边界的行动/表达选项，解释适用条件与潜在代价。可附可编辑的示例表达。
7. **边界与风险提示**：明确这只是基于用户提供材料的辅助复盘，不是诊断、治疗或专业咨询；若识别到风险，展示相应求助建议。

输出需标记不确定性。对第三方动机、人格、忠诚度或诊断不得使用确定性口吻。引用原始材料时不得编造或改写成不存在的原句。

## 7. 高风险与安全处理

### 需要触发特殊处理的内容

- 明确自伤、自杀意图或正在发生的生命安全威胁。
- 暴力、胁迫、跟踪、控制、威胁、性暴力或用户表示无法安全离开。
- 用户要求操纵、威胁、跟踪、报复、套取隐私或伤害他人。
- 疑似未成年人或其他需要特别保护的情形。

### MVP 行为

- 对涉及自伤、自杀或正在发生的危险，不生成普通关系分析或“忍耐/挽回”建议；以简洁、支持性的语言鼓励立即联系当地紧急服务、可信任的人或专业支持渠道。
- 不承诺本 MVP 有人工实时接管能力；页面清楚说明服务不是紧急援助渠道。
- 对暴力或胁迫情境优先提供安全导向、避免责备用户，不鼓励直接对质或冒险行动；提示用户寻找可信任的现实支持。
- 对操纵、跟踪、报复等请求拒绝协助，并提供尊重边界的替代表达。
- 测试环境建立人工复核流程；任何真实危机个案的存储和处理流程需在招募前确定，并由项目负责人指定可执行的升级联系人/资源。

## 8. 数据、隐私与同意

### 数据原则

- 只收集完成一次分析和评估体验所必需的数据。
- 页面提供清晰说明：上传材料可能包含用户本人及第三方的个人信息；用户应先脱敏并确认有权提交。
- 产品改进授权与服务使用分开，默认关闭、单独勾选、可撤回；拒绝授权不影响分析服务。
- 不将未经单独授权的用户原始聊天材料用于模型训练或公开展示。
- 不把“保存于本地”模糊表述成“仅保存在用户设备”。内测前要明确数据到底存在哪台设备/服务器、谁可访问、保留多久、如何删除。

### MVP 建议的数据分层

1. **本次服务数据**：原始文本/图片、OCR 文本、用户补充背景、生成报告。为了提供本次分析而临时处理；应设定短保留期并支持用户删除。
2. **用户本地副本**：报告可由用户主动下载或保存在浏览器本地；明确浏览器清理、共享设备等限制。
3. **改进数据（可选）**：只有用户明确同意后，保存去标识化/脱敏版本及结构化反馈，用于人工质量审阅和评测。授权撤回后停止后续使用并按流程删除可删除的数据。
4. **运行日志**：只记录必要的错误、时延、模型版本和安全事件信息；避免写入原始聊天内容。

具体存储位置、加密方式、保留期限、访问控制、备份清除和第三方模型服务商处理方式，是内测上线前必须补齐的工程与合规事项；当前 PRD 不声称已满足法律要求。

## 10. 质量与验收指标

首轮不预设商业成功门槛；开发完成后、内测招募前，与用户共同设定样本量、通过标准及付费测试方式。

### 产品质量指标

- 端到端完成率、分析失败率、平均响应时长。
- OCR 识别后用户修正比例和主要错误类型。
- 事实与推断混淆率、无依据断言率、遗漏关键反证率、虚构引用率。
- 不确定性表达质量、建议可执行性、不同输入下输出稳定性。
- 高风险识别召回率及误报率；高风险案例不得只凭单一 LLM 自评。
- 用户反馈：有帮助程度、具体可执行性、信任感、隐私顾虑。

### 内测验收建议

- 至少完成一组人工编写并人工标注的测试案例，覆盖信息缺失、单方叙述、相互矛盾材料、要求站队、暴力/自伤风险、OCR 错误、诱导操控请求。
- 关键事实均可回溯到用户输入；系统不伪造引用。
- 高风险场景通过人工审阅后才允许邀请外部测试用户。
- 删除流程、授权撤回流程、数据位置说明和访问权限已实际演练。
- 任何“稳定”或“安全”上线结论须基于记录的评测结果，而非开发者主观感觉。

## 11. 内测与研究设计

### 第一轮：学生/开发者样本的可用性、分析质量与信任测试

- 渠道：AI 社团、同学、开发者社群、熟人网络或导师合作资源；优先招募近期经历相关困扰的成年人。
- 目标：验证用户能否自然讲述问题、Agent 是否理解上下文并给出有用优化建议、必要追问是否适度，以及隐私说明是否清楚。
- 记录：完成/退出、用户纠正、建议具体性和可执行性、迎合/臆测/责备/遗漏、追问必要性、后续行动、授权选择、删除操作和样本来源偏差。

### 第二轮：价值与付费验证（上线前另定）

- 在产品完成并获得初轮质量反馈后，再确定测试价格、样本量和付费阈值。
- 优先观察真实付费/预售行为，不把“愿意付”“觉得不错”当作付款证据。
- 同步记录招募来源，区分同学/AI 社团/非熟人目标用户，避免熟人样本偏差。
- 可并行探索情感博主等 B2B 需求，但独立记录，不与 C 端结果混算。

## 12. 关键假设与验证方式

| 假设 | 低成本验证 |
|---|---|
| 用户愿意提交经脱敏的聊天材料 | 测试不同输入方式和隐私说明，观察真实提交与退出比例 |
| 情感专长 Agent 比直接问通用 AI 更有价值 | 同一案例进行盲测比较，访谈用户在理解、分析和优化建议上的具体差异，不只比较满意度 |
| “事实/解释/推断分层”能提升信任 | 对比有无分层的报告并收集理解和纠错表现 |
| 单次报告可能成为可行收费方式 | 内测质量通过后做真实价格测试或小额预售 |
| B2B 内容工具可能更早产生收入 | 单独访谈博主/机构，测试具体工作流和付费试点意愿 |

## 13. 技术方案原则（不限定具体技术栈）

- 工作流优先采用可追踪的固定步骤：输入校验 → OCR/文本规范化 → 高风险筛查 → 事实/解释抽取 → 多解释分析 → 独立安全与证据检查 → 输出格式校验。
- 模型生成不得直接决定高风险处置；安全规则、人工审查和可测试的判定逻辑应有明确职责。
- 分析核心与网页 UI 解耦；同一核心供 CLI、网页调用，保留输入、模型版本、提示词版本和评测结果的可追踪性。
- 首版不做长期记忆、微调、复杂多 Agent 协商或外部关系知识图谱。
- 图片识别结果需显式标记为机器识别，并允许用户核对；不把识别出的内容自动视为完整事实。
- 模型供应商、数据传输地点、日志策略和服务条款需在接入前核实并写入数据说明。

## 14. 发布边界与待确认事项

### 发布前必须完成

- 确认使用的模型 API 是否会留存或训练输入数据，以及数据传输和处理位置。
- 完成数据流程图、保留期限、删除方式、访问权限和授权文案。
- 确认危机内容的响应文案、求助渠道和内测人工处理责任人。
- 进行中国大陆适用法规的专业合规评估，尤其是服务是否构成持续性情感互动、个人信息和敏感个人信息处理、未成年人排除/识别、算法与安全评估义务。
- 不在完成上述事项前公开投放或接受敏感材料的真实用户内测。

### 留待后续决定

- 产品名、视觉风格、具体模型和云/本地部署方式。
- 免费额度、价格、支付方式、是否预售、商业成功阈值。
- 测试样本量与周期、首批具体场景优先级。
- 公开投放平台、博主合作形态、B2B 产品是否单独立项。

## 15. 当前建议的决策门

- **进入封闭内测**：端到端流程可用，质量评测与高风险审查达到团队设定门槛，数据和删除流程可解释且可操作。
- **继续迭代**：用户能指出具体价值，但输出或隐私体验仍有可修复问题。
- **调整场景**：用户愿意试用，却无法识别相较免费通用 AI 的独特价值，或目标场景过于宽泛。
- **暂停/停止**：关键安全错误无法收敛；用户不愿提交完成任务所需的材料；真实付费验证长期没有信号且成本/质量没有改善。

以上是验证型 MVP 的初版 PRD，定价和商业成功阈值故意留待首轮产品质量与用户反馈之后决定。
