# PRD：情感沟通复盘助手（C 端 MVP）

- 版本：1.1
- 日期：2026-10-20
- 范围：C 端 MVP 产品需求基线

本文件是项目唯一 PRD，维护功能、体验、隐私、安全与非目标边界。它用于确定产品需求，不作为代码接口、数据结构或实现细节的直接技术依据。代码实现以[工程设计说明](../C端开发/工程设计说明.md)和[阶段任务与验收标准](../C端开发/阶段任务与验收标准.md)为准；范围变化须同步相关文档并在[开发进度日志](../C端开发/开发进度日志.md)记录。

## 1. 产品概述

### 一句话描述

用户提交一段经过处理的关系沟通材料和必要背景，获得一份区分事实、解释与推断的复盘，帮助其理解可能的沟通误差，并选择下一步如何表达。

### 产品形态

- 通过中文网页提供输入、分析、结果查看、反馈和删除能力，支持桌面和移动端浏览器。工程阶段 1 的 CLI 仅供内部成年人受控工程使用；Web 在工程阶段 3 建设并验证，满足试用条件后于阶段 4 向成年测试用户开放，不表示公开发布。

### 产品定位

这是一个“沟通复盘与下一步表达建议”Agent，不是陪伴式虚拟伴侣、心理治疗或关系诊断服务。它不替用户断言对方的真实动机，也不替用户决定是否分手、复合或结婚。

## 2. 用户与待解决问题

### 服务对象

面向 18 岁及以上、希望梳理亲密关系沟通困惑的个人用户。MVP 不面向未成年人提供服务。

### 用户问题

- 用户拿到一段聊天后容易反复猜测对方意图，难以区分原话与自己的解读。
- 通用 AI 回答可能迎合提问者、过度推断或给出听起来确定但证据不足的建议。
- 用户需要一个低压力的方式，厘清沟通卡点，并准备一条更清楚、尊重边界的表达。

### 首版核心任务

“我把自己的感情经历和矛盾讲给你听，请理解上下文，帮我分析问题在哪里、我可能做错或忽略了什么、有哪些其他解释，以及我接下来可以怎么处理。”优化建议和决策支持是核心价值。

## 3. 产品目标与非目标

### 目标

1. 用户能在无需注册的情况下完成一次端到端复盘。
2. 输出可读、具体、可执行，并清晰区分材料事实、用户解释和模型推断。
3. 用户能指出报告中有帮助、无依据、遗漏或不安全的部分。
4. 用户可自主选择是否允许将脱敏材料和反馈用于产品质量改进。

### 非目标（MVP 不做）

- 长期陪伴、虚拟恋人、角色扮演、拟人化亲密关系或连续聊天型关系服务。
- 挽回、操控、PUA、监视伴侣、诱导对方作决定等功能。
- 精神障碍诊断、心理治疗、婚姻治疗、法律意见或专业咨询替代。
- 对对方是否爱用户、是否出轨、人格类型、依恋类型或关系结局作确定性判定。
- 账号体系、跨会话长期记忆、社交功能、支付系统、公开内容社区、自动触达第三方。
- 将测试样本或报告满意度直接解释为市场规模或商业成功。

## 4. 用户流程与对话方式

1. 用户进入网页，阅读用途、服务边界、数据处理说明和年龄限制；提交任何材料前完成成年人确认，拒绝或未完成确认不能继续提交。具体保护方案须在试用前评估并实际验证，不能将一个勾选框视为充分的年龄保护。
2. 用户选择输入方式：粘贴文本、手动描述事件、上传聊天截图，或在语音入口通过独立开放验收后录制/上传一段语音讲述。
3. 页面提醒用户先遮盖姓名、头像、电话号码、账号、地址等身份信息，并尽量取得截图中其他人的适当授权；首版提供脱敏操作指引，不宣称自动脱敏无误。
4. 用户可以直接用自然语言讲述经历、矛盾或问题；页面仅提供可选提示帮助组织信息，不要求先完成长问卷。
5. 用户确认提交材料，并单独选择是否允许将脱敏材料与反馈用于产品改进。默认不勾选；拒绝不影响本次分析。
6. 系统解析文本、图片或音频，展示 OCR/ASR 识别文本及材料摘要供用户确认/修正后再分析。解析失败时允许改用文本或手动输入。
7. Agent 先基于已有内容理解和分析；只有缺失信息会实质改变判断或建议时，才简短追问。它可主动引导用户补充关键背景，但不得反复盘问或把体验做成诊疗式逐题问答。
8. Agent 给出针对用户困惑的分析和具体优化建议，后续交互限于必要且可跳过的有限澄清、补充和修正。暂停中的分析沿原运行恢复；完成后的修正通过新输入版本和新运行更新判断，不修改已发布结果。不提供任意连续聊天，扩展持续自由对话须另行定义协议、状态及验收。适合收束时生成可回看的复盘总结，TTS 入口通过独立开放验收后，用户可主动选择播放已校验的总结或建议。
9. 高风险内容触发安全回应或停止常规建议。用户可提交可选反馈；离开前可删除本次记录。

无需注册。用户只能访问和操作本人提交的材料及其结果；仅凭资源标识不能访问他人内容。MVP 不提供跨设备恢复，并须向用户说明访问凭证丢失或过期后的影响。系统应先提供基于现有材料可形成的有限分析；只有安全风险要求停止普通分析时，才仅提供安全回应。

## 5. 输入要求

### 支持的输入

- 纯文本聊天记录。
- 用户手动描述的沟通事件。
- 聊天截图图片；通过 OCR/视觉模型提取内容后，必须允许用户检查和修改识别文本。
- 用户录制或上传的语音讲述；通过 ASR 转写后，必须允许用户检查和修改识别文本。

### 输入限制

- 首版支持静态图片和短音频，不支持视频、社交平台账号授权或自动抓取。
- 限制单次图片数量、音频时长和文件大小，具体上限由实现与模型成本确定，并在页面明确显示。
- 图片 OCR 和音频 ASR 结果均为机器识别文本，必须由用户确认或修正；识别失败可回退为文本输入。
- TTS 仅在用户主动操作时播报已通过安全与质量检查的结果，不替代可阅读的文本输出。
- 提示用户仅提交完成分析所需的最少材料；不鼓励上传完整聊天历史、身份证件、医疗记录、财务资料或其他无关敏感信息。
- 不向未满 18 岁用户提供服务；年龄提示不能替代年龄保护措施。

## 6. 输出报告结构

分析可以自然对话呈现，不要求每轮套固定模板；适合总结时，可包含：

1. **问题摘要**：复述用户希望解决的问题，不替用户改变目标。
2. **材料中明确发生的事**：只列有输入依据的内容；尽量标注对应原句或时间点。
3. **用户的感受与解释**：明确注明来自用户自述，不把它们升级成客观事实。
4. **可能的沟通模式 / 多种解释**：至少提供两个合理假设（如果材料足够）；分别说明支持依据、反证或缺失信息，不做对方内心断言。
5. **尚不清楚的地方**：指出会显著影响结论的缺失背景；只在必要时提澄清问题，同时基于当前信息先提供有限分析。
6. **优化建议与下一步**：说明用户自身可调整之处，提供具体、非操控且尊重边界的行动/表达选项，解释适用条件与潜在代价。可附可编辑的示例表达。
7. **边界与风险提示**：明确这只是基于用户提供材料的辅助复盘，不是诊断、治疗或专业咨询；若识别到风险，展示相应求助建议。

输出需标记不确定性。对第三方动机、人格、忠诚度或诊断不得使用确定性口吻。引用原始材料时不得编造或改写成不存在的原句。

## 7. 高风险与安全处理

### 需要触发特殊处理的内容

- 明确自伤、自杀意图或正在发生的生命安全威胁。
- 暴力、胁迫、跟踪、控制、威胁、性暴力或用户表示无法安全离开。
- 用户要求操纵、威胁、跟踪、报复、套取隐私或伤害他人。
- 疑似未成年人或其他需要特别保护的情形。

### MVP 行为

- 疑似用户本人未成年时停止普通分析并提供安全导向回应，不能仅因材料提及未成年人就断定用户年龄；确认误收未成年人材料后停止服务、取消在途处理、阻断内容访问并执行关联数据删除，仅保留查询删除状态所需的最小回执。阶段 1 验证风险路由，阶段 3 落实页面/API 年龄确认及误收拒绝、删除流程，阶段 4 招募前完成运行核验。

- 对涉及自伤、自杀或正在发生的危险，不生成普通关系分析或“忍耐/挽回”建议；以简洁、支持性的语言鼓励立即联系当地紧急服务、可信任的人或专业支持渠道。
- 不承诺本 MVP 有人工实时接管能力；页面清楚说明服务不是紧急援助渠道。
- 对暴力或胁迫情境优先提供安全导向、避免责备用户，不鼓励直接对质或冒险行动；提示用户寻找可信任的现实支持。
- 对操纵、跟踪、报复等请求拒绝协助，并提供尊重边界的替代表达。

## 8. 数据、隐私与同意

### 数据原则

- 只收集完成一次分析和评估体验所必需的数据。
- 页面提供清晰说明：上传材料可能包含用户本人及第三方的个人信息；用户应先脱敏并确认有权提交。
- 产品改进授权与服务使用分开，默认关闭、单独勾选、可撤回；拒绝授权不影响分析服务。
- 改进授权绑定告知版本、用途、状态、时间和数据版本范围，仅覆盖告知的人工质量审阅/评测。撤回后停止使用并清理可控改进副本和评测派生数据；模型训练、公开展示等扩大用途须另行明确授权。
- 不将未经单独授权的用户原始聊天材料用于模型训练或公开展示。
- 不把“保存于本地”模糊表述成“仅保存在用户设备”。内测前要明确数据到底存在哪台设备/服务器、谁可访问、保留多久、如何删除。

### MVP 建议的数据分层

1. **本次服务数据**：原始文本/图片/音频、OCR/ASR 转写、用户确认/修正版本、分析结果和 TTS 音频。为了提供本次分析而临时处理；应设定短保留期并支持用户删除。
2. **用户本地副本**：报告可由用户主动下载或保存在浏览器本地；明确浏览器清理、共享设备等限制。
3. **改进数据（可选）**：只有用户明确同意后，保存去标识化/脱敏版本及结构化反馈，用于人工质量审阅和评测。授权撤回后停止后续使用并按流程删除可删除的数据。
4. **运行日志**：只记录必要的错误、时延、模型版本和安全事件信息；避免写入原始聊天内容。

存储位置、加密方式、保留期限、访问控制、备份清除和第三方服务商处理方式必须在向用户提供服务前明确告知并落实。本文不构成法律合规结论。

删除应覆盖业务数据、原件、转写、TTS、缓存、checkpoint 及关联改进副本，并阻止在途任务写回。明确显示处理中、完成或失败及未清理范围，保留仅供查询删除状态的最小回执；不能把请求已接收当作全部删除。撤回改进授权不自动删除服务数据；删除服务数据同时清理关联改进副本。用户已下载的副本无法远程撤回。

## 10. 反馈类型

反馈绑定用户本人会话中的已发布结果版本，可附选填说明。提交服务反馈不等于同意将材料用于产品改进；改进用途仍需单独授权。

| 类型 | 展示名称 | 含义 |
|---|---|---|
| `helpful` | 有帮助 | 有助于理解问题或选择下一步表达 |
| `unsupported` | 无依据 | 断言、解释或建议缺少材料支持 |
| `omission` | 遗漏 | 漏掉重要事实、反证、背景或选项 |
| `unsafe` | 不安全 | 含可能造成伤害、操控或其他安全风险的内容 |

文本、图片入口须通过权限、上传限制、确认/修正、失败回退和删除验收。ASR/TTS 还须完成实际适配器、音频限制、供应商留存/训练/删除说明及端到端验证后分别开放；未达门槛时关闭相应入口并保留文本替代流程，工程建设义务不变。具体证据和门槛维护在阶段任务与验收标准。
