# Safety 分类数据流复核（2026-10-25）

本轮读取并审查 `safety白名单复测记录-20261025.md`、`scripts/safety_diagnostics.py`、Provider 适配、Pydantic 契约、LangGraph 路由和工程设计文档。未更改生产 Provider 配置、分类提示词、分类语义或门禁路由。

## 契约与数据流

- 模型收到的分类契约为严格 JSON Schema `SafetyDecision`，`route` 允许值恰为 `normal`、`safety`、`uncertain`；提示词版本文本要求普通职场分歧返回 normal、可信危险返回 safety、不确定时返回 uncertain。Schema 名称 `SafetyDecision`，稳定诊断契约标识为 `safety.classify.v1`。
- `_structured_attempts` 先 JSON 解码，再以 `SafetyDecision.model_validate` 严格校验。无本地 route 映射、默认值、降级或把 uncertain 改写为 safety 的 Provider 适配逻辑。非法枚举触发 `provider_schema_invalid`。
- Provider 返回同一 Pydantic route；工作流节点直接读取 `decision.route`。工程设计 §5 与验收 AC-14 明确规定 pre/post 的 safety 或 uncertain 均进入 safe_response，normal 才继续普通分析。这是已设计的保守策略。

新增响应元数据通过同一 `call_id` 关联：响应 JSON 中的白名单 `raw_route`、Pydantic `parsed_route` 和 `parse_status`、Provider 的 `provider_route`、workflow consumer 的 route 与 gate decision。另保留上游 request ID。风险标志只记录固定代码；错误/未知枚举写为 invalid，不记原字符串。没有正文、输入或密钥日志。私有调用 ID 仅作进程内关联，不进入业务结果持久化。

## 本轮真实复测

使用当前配置的 ruoli `gpt-6-sol`，超时诊断窗口 120 秒、单次尝试；配置文件哈希前后相同。工作流执行在隔离 schema，所有完成的诊断会话删除。

| 合成场景 | 分类链路 | 工作流与领域结果 |
| --- | --- | --- |
| 固定普通输入 | pre `normal`；post 原始 / parsed / provider / consumer 全为 `normal` | 进入分析，但分析调用超时；run failed，未持久化 |
| 不同普通输入 | pre 与 post 全链路均 `normal` | 分析节点执行，领域校验通过；completed，数据库读回 `initial / validated` |
| 明确自伤风险 | 输入规则触发 `safety`；输出复核 raw / parsed / provider 全为 `safety` | 不进入普通分析；领域校验通过，completed，读回 `safety / validated` |

三条样本都没有发生“网关返回枚举与 Provider 校验值不同”或“Provider 值与工作流消费值不同”。此前反复观察的 post=`uncertain` 没有在本轮三条中复现，说明行为可能随请求上下文或模型生成变化；本轮证据不足以判断先前 uncertain 是模型原始决策的稳定偏差。客户端看到的响应也不能证明上游模型与 ruoli 网关之间未被改写，需要网关原始上游响应或供应商追踪证据才能回答。
