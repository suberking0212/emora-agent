## 固定实验

运行器 `scripts/safety_consistency.py` 仅调用模型理解和分类接口，不建工作流、不读写数据库、不输出最终用户结果。样本注册表包含：

- 普通：既有固定合成职场样本、既有普通交叉样本、既有信息不足样本。
- 风险：自伤、暴力/限制离开、有害跟踪与操纵请求。

每个样本使用固定 UUID 与不变输入重复 pre。每个普通样本还运行 post 双臂：同一个模型理解对象；同一个人工校准理解对象。调用顺序按重复轮次交错，以减小时间漂移偏差。风险样本同样测模型理解后的 post。人工校准文本目前只是候选；如经用户审阅确认，再用 `--calibration-status human_confirmed` 标记。候选文本严格区分已知陈述与未知信息，未知信息不自动推成风险。

每行记录输入类型/固定输入哈希、理解臂与理解快照、模型、`PROMPT_VERSION`、分类器源码哈希、重复轮次、pre/post、路由、原始/解析路由、解析状态、固定风险码和耗时。模型理解快照只针对仓库内合成输入；不读取、恢复或回写历史会话。输出文件用 `x` 模式避免覆盖既有证据，配置 SHA-256 前后核对。汇总输出包括普通非 normal 次数（普通误拦截代理指标）、风险 normal 次数（风险漏检）、路由波动，以及同轮 post 双臂路由差异。

运行：

```sh
uv run python -m scripts.safety_consistency \
  --output doc/阶段一测试指导/safety-consistency-20261026.jsonl \
  --repeats 3 --timeout 90
```

结束后读取同名 `.summary.json`。不同理解臂的差异可以显示理解内容是否影响 post 输出，但不能单独证明因果：内容差异同时改变了分类 payload；重复请求也可能有模型随机性/服务端变化。固定样本数量很小，是诊断而非统计性安全认证。

## 决策标准

- 同一理解臂多次路由波动：先查模型/服务端分类稳定性和调用语义；可再测试提示词，不据小样本直接改门禁。
- 模型理解臂不确定、人工校准臂稳定 normal，且两臂输入和提示版本均固定：说明理解表述值得单独评估；先完善理解上下文/表示并扩样复测。
- 两个理解臂对普通内容都不稳定：检查分类提示词对“信息不足但无风险”的操作定义和示例。
- 风险样本出现 normal：视为漏检信号，优先做安全错误分析并保持当前保守策略。
- 只有扩大样本后误拦截、漏检和波动均满足验收阈值，才提交策略变更评审。当前结果不自动改变 `uncertain -> safe_response`。

## 本轮判断

先前提出“优先做分类提示词的实验性修订”的排序撤回。已有数据不足以确定应先改分类器、理解上下文还是策略；这些材料尚未验证目标用户代表性，所谓误拦截也只是探索性标签下的计数。先明确 post 要回答的问题、普通信息不足应如何处理，以及风险不确定与任务不明确的边界。

分类上下文消融也暂不执行。是否继续、采用哪些样本及保留哪些任务语义，应由产品任务与 post 定义复核决定；不能把精简摘要当成正确理解的天然标准。

本轮不建议改门禁策略。保持 uncertain 进入 safe_response，直到扩大普通与风险集、加入隐晦风险/否认/引用/历史事件等边界输入，并设定误拦截、漏检和波动验收阈值后再评审。三个明确风险样本不足以支撑放宽策略。
