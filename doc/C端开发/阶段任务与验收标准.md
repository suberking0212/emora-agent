# 阶段任务与验收标准

文档编号：AC-001；版本：2.1；日期：2026-10-20。

本文件单独维护阶段规划、测试策略、验收规则和证据格式；编码类型、路由和状态约束以[工程设计说明](工程设计说明.md)为基线。项目状态、阶段交付与验收结论只记录在[开发进度日志](开发进度日志.md)，技术缺口记录在[技术债务清单](技术债务清单.md)。产品需求以唯一的[C 端 MVP PRD](../C端产品设计/PRD-情感沟通复盘助手-C端MVP.md)为准；PRD 不作为代码接口或实现细节的直接依据。

## 阶段与开放范围

本文件保留阶段 0–5 一套编号。阶段 1–3 为工程建设与验收阶段；阶段 4 为实际用户试用与质量验收，阶段 5 为价值、付费与方向决策。“用户开放范围”是各阶段的入口及使用条件，不另设产品阶段编号。工程能力是否完成、入口是否开放须分别记录；暂不开放不能作为推迟、省略或取消对应阶段工程要求的理由。

| 阶段 | 工程或验证职责 | 用户开放范围与条件 |
|---|---|---|
| 1 | CLI、模型、图、PostgreSQL 及基础服务能力 | 内部成年人受控工程使用；文本、文本文件、图片识别确认、分析、澄清恢复、查看和删除；不向普通用户开放 |
| 2 | 数据生命周期、授权、删除扩展与只读检索 | 不新增用户入口，不交付 Web UI；已有能力供内部验证，检索默认关闭 |
| 3 | API、Web、ASR/TTS 具体适配器 | 建设 Web 文本、图片、确认/修正、有限澄清、报告复制/下载、反馈、改进授权及撤回、删除与状态入口；阶段内先内部验证，满足开放门槛后于阶段 4 开展受控试用；ASR/TTS 另须通过 AC-36 |
| 4 | 实际成年用户试用与质量验收 | 满足阶段 1–3 验收及试用前置条件后开放受控 Web 试用；不等同公开发布 |
| 5 | 价值、付费与方向决策 | 不自动扩大功能或发布范围，新增开放须单独决策并验收 |

## 验收证据格式

每项记录实现版本、检查日期、执行命令或操作、预期与实际状态、退出码/错误码、证据路径及通过/失败/未验证。文档模板、抽象类、节点声明或依赖声明不能作为功能完成证据。未执行项标记未验证，不推断通过。测试逻辑与产品运行模块分离。

|---|---|---|

## 阶段 1：CLI、模型、图与 PostgreSQL

| 编号 | 工程落点 | 必须核验的行为 |
|---|---|---|
| AC-10 | 工程 §2/§6/§7.1 | PostgreSQL 可通过 Alembic 初始化；锁定依赖后 CLI 可启动；输入选项互斥；缺少模型配置返回明确错误 |
| AC-11 | 工程 §3 | 三类 modality、确认状态、UUID/UTC/JSON 序列化、未知字段拒绝；模板与实现字段一致 |
| AC-12 | 工程 §3.1 | 未确认/空输入、版本错配、重复 ID、悬空引用、越界切片、错误原文、非法来源均失败 |
| AC-13 | 工程 §4 | 实际模型适配器按 AnalysisCandidate schema 返回结构化对象；OCR 可调用实际 provider；失败/超时不交付候选正文；仅超时、限流和可恢复供应商 5xx 在总调用次数及时间预算内自动重试，参数/schema/授权错误不重试；限流映射 provider_rate_limited |
| AC-14 | 工程 §5 | 前置、理解后与输出检查均生效；safety/uncertain 不进入普通建议；修订最多一次 |
| AC-15 | 工程 §5/§6 | AnalysisCandidate 经校验、候选保存回读和安全复核后才发布 AnalysisResult；仅发布版本可查询/输出；初步结果发布后才暂停；进程重启或 PostgreSQL 连接重建后可恢复；skip=true 无输入且沿用当前版本，skip=false 提供新的当前 confirmed/corrected 版本；非 waiting_clarification、过期轮数和版本错配拒绝恢复 |
| AC-16 | 工程 §5/§6 | 结果不可变、保存失败不报完成；同 request_id 相同 payload 恢复同一操作，不同 payload 返回 idempotency_conflict；事务回滚和并发旧任务不能覆盖新版本；外部 retryable 与服务端 provider 自动重试分别验证 |
| AC-17 | 工程 §8 | JSONL 独立输出、字段齐全；input_summary 为 null；无正文、prompt、密钥或供应商原始响应 |
| AC-18 | PRD §6/工程 §3 | 结果包含问题摘要；假设关联支持证据和反证；安全结果包含安全回应且不含普通建议 |
| AC-19 | 工程 §3/§8 | RunEvent.status 只接受 started/succeeded/waiting/failed/cancelled；步骤事件状态不替代 RunRecord.status |
| AC-1A | 工程 §6/§7.1 | 内部服务可按主体、会话和已发布结果保存四类反馈；拒绝改进授权仍可分析；授权状态及版本范围可更新、持久化回读；CLI 无对应入口 |
| AC-1B | 工程 §5 | 输入识别为疑似未成年人时走 safety/uncertain，不进入普通建议；补充和修正后同样检查 |

阶段 1 是无需 Web/API 的 CLI 最小完整闭环，直接使用 PostgreSQL 业务库和 PostgreSQL checkpoint，包含用户输入确认、分析结果验证和保存、澄清恢复及数据删除；用户反馈和产品改进授权必须在服务层实现，但阶段 1 CLI 暂不开放对应用户入口。阶段 1 需要本地可复现的 PostgreSQL 开发实例或等价托管实例。ASR/TTS 在本阶段定义并验证接口，具体适配器归阶段 3。CLI 暂不提供音频输入、TTS、feedback 或 consent 命令；工程服务与数据层仍须落实反馈保存及改进授权更新。阶段 1 用内部契约检查验证这些能力，不能以命令未开放替代实施或验证。

## 阶段 2：数据生命周期与授权扩展

| 编号 | 工程落点 | 必须核验的行为 |
|---|---|---|
| AC-20 | 工程 §6 | 阶段 1 PostgreSQL schema 可升级；迁移前后 ID、输入/结果版本、授权和删除标记一致 |
| AC-21 | 工程 §6 | 读写、恢复、文件与缓存均校验归属；删除会话阻断读取及在途写回 |
| AC-22 | 工程 §6 | 删除开始即阻断读取和在途写回；相同会话重复删除返回同一 deletion_id；失败重试复用任务且只清 pending_scopes，每次尝试留审计记录；残留未清不报 completed；删除操作 request_id payload 冲突返回 idempotency_conflict |
| AC-23 | 工程 §3/§6 | 改进同意默认 denied；拒绝不影响分析；撤回停止该用途并清理相应副本 |
| AC-24 | 工程 §4/§6 | 检索默认关闭；启用后只返回 approved 且获准来源版本，引用能定位全文切片 |
| AC-25 | 工程 §6 | TTL 必填且范围合法；到期拒绝内容访问；备份恢复先重放删除标记 |

阶段 2 复用阶段 1 的 PostgreSQL 业务库和 checkpoint，完成多主体授权与资源隔离、上传资产与派生数据清理、删除任务重试、改进数据撤回和备份恢复处理。本阶段为阶段 3 的 API/Web 提供授权与生命周期基础，不交付 Web 前端或 HTTP 用户入口；基础能力在阶段 1 已要求的范围仍须阶段 1 实现。不得把数据库切换作为阶段 2 的交付内容，也不得将阶段 1 已验收的 CLI 行为作为阶段 2 的新实现结论。

## 阶段 3：API、Web、ASR/TTS

| 编号 | 工程落点 | 必须核验的行为 |
|---|---|---|
| AC-30 | 工程 §7.2 | 全部路由、请求/响应、错误状态与 OpenAPI 一致；客户端类型由契约生成 |
| AC-31 | 工程 §7.2 | Cookie 属性、随机令牌摘要、过期、Origin/CSRF 校验；跨主体读写/下载/恢复/删除拒绝 |
| AC-32 | 工程 §4/§7 | 文本、图片、音频确认与修正；上传大小/MIME/签名拒绝；ASR/OCR 失败不进入图 |
| AC-33 | 工程 §7.2 | SSE 不发送未校验正文，重连可续取或重新查询；API 与 CLI 共用领域入口 |
| AC-34 | 工程 §7.2 | TTS 主动触发，生成与返回均复核当前结果和删除状态；旧版本拒绝，失败保留文本 |
| AC-35 | PRD F-01–F-10、F-03a、F-13/工程 §7 | 前端满足 PRD 功能范围；反馈枚举与 PRD 四类反馈一致；无前端密钥或正文日志 |
| AC-36 | 工程 §4/§7.2 | ASR/TTS 实际适配器可运行；图片数量、音频时长、文件大小、MIME 和签名限制生效；ASR 转写可确认/修正、失败可回退文本；TTS 主动触发且失败保留文本；供应商留存/训练/删除政策已核实告知，原件及派生文件删除演练通过，端到端验证通过后才开放相应入口 |
| AC-37 | 工程 §7.2 | Web 在收取材料前完成成年人确认；缺失或否认确认的 API 请求被拒绝且不收材料；疑似未成年人停止普通分析，确认误收后取消任务、阻断内容访问并提交删除，覆盖关联副本且仅留最小回执；页面、API 直连及在途任务场景均有运行证据 |

ASR/TTS 入口分别记录开放状态及证据，门槛未满足时保持关闭，继续提供已验收的文本/图片路径并记录原因；接口和适配器仍按阶段要求建设，缺少适配器验收不能宣称阶段 3 全部完成。图片上传也须通过 AC-31、AC-32 的归属、限制、确认和失败回退，以及文件删除核验。候选结果、数据库/checkpoint、provider 原始错误、密钥、共享资料管理不作为 Web 用户入口。

阶段 4 试用开始前须记录服务商留存/训练/删除政策、实际保留期限、适用合规与内容来源授权核查及成年人确认和误收处理方式；并完成会话隔离、私有文件访问、撤回和删除的运行核验。证据不足保持未验证，不以文档齐备代替运行结论。

## 阶段 4：实际用户试用与质量验收

完成阶段 1–3 并满足外部试用条件后，开展成年用户手动试用。验收只使用实际运行、用户纠正、反馈、退出和删除请求形成的授权证据。阶段交付物、验收结果和限制以简洁日志记录于[开发进度日志](开发进度日志.md)，不另建验收报告。

验收关注：端到端完成与失败、事实和推断可追溯性、无依据断言、必要澄清、安全路由、隐私告知、授权撤回、删除完成度和用户反馈。所有结论须标注证据范围；无证据保持“未验证”。

## 阶段 5：价值、付费与方向决策

在阶段 4 完成后，若需要开展价值或付费验证，单独记录样本来源、测试条件、实际付款或预售事实及限制。不得用意愿、满意度或市场调研数字替代付款证据。结论记录于[开发进度日志](开发进度日志.md)。
