# 阶段任务与验收标准

文档编号：AC-001；版本：2.2；日期：2026-10-20。

本文件单独维护阶段规划、测试策略、验收规则和证据格式；编码类型、路由和状态约束以[工程设计说明](工程设计说明.md)为基线。项目状态、阶段交付与验收结论只记录在[开发进度日志](开发进度日志.md)，技术缺口记录在[技术债务清单](技术债务清单.md)。产品需求以唯一的[C 端 MVP PRD](../C端产品设计/PRD-情感沟通复盘助手-C端MVP.md)为准；PRD 不作为代码接口或实现细节的直接依据。

## 验收证据格式

每项记录实现版本、检查日期、执行命令或操作、预期与实际状态、退出码/错误码、证据路径及通过/失败/未验证。文档模板、抽象类、节点声明或依赖声明不能作为功能完成证据。未执行项标记未验证，不推断通过。测试逻辑与产品运行模块分离。

“设施已落实、入口未开放”以对应阶段的完整可执行代码、必要存储/迁移、授权与失败处理、内部集成测试和真实执行证据验收。分别记录设施完整度、内部执行验证和 CLI 是否暴露入口；CLI 阶段不开放仅表示不提供终端命令或交互，不追加专门的入口 gate、绕过防护或配套校验机制。设施自身原有授权、schema、超时、幂等和错误处理要求照常落实；接口、stub、占位目录或配置开关不能代替完整实现。此原则适用于该阶段明确要求的基础设施，不把未来阶段的功能提前纳入；当前仅有设计文档，设施完整度和运行行为均未验证。

AC-1E 在首次基线建立时执行当前版本回归；旧版本 checkpoint/迁移测试在实际存在历史版本和升级时执行，不创建虚构历史运行。多 runtime 调度和动态技能插件加载不作为阶段 1 前置条件；§4.1 规定的工具设施必须在阶段 1 完整实现并内部验收，CLI 仍不暴露工具选择入口。工具链内部测试不等于实际模型的 tool calling 能力通过；支持该能力的适配器须另有真实模型调用证据，确实不支持则验证明确拒绝。

阶段 1 是无需 Web/API 的 CLI 最小完整闭环，直接使用 PostgreSQL 业务库和 PostgreSQL checkpoint，包含用户输入确认、分析结果验证和保存、澄清恢复及数据删除。产品改进授权所需的数据模型、服务方法、归属校验、撤回和删除能力必须同步完整建设并由内部测试验证真实数据库状态与副本清理；阶段 1 CLI 不启用产品改进授权或反馈入口，也不因未授权或未反馈而阻断分析及其他必要流程。内测阶段的反馈调研通过独立的人工或研究流程收集，不作为 CLI 使用前提。阶段 1 需要本地可复现的 PostgreSQL 开发实例或等价托管实例。ASR/TTS 在本阶段定义并验证接口，具体适配器归阶段 3。

## 阶段 4：实际用户试用与质量验收

完成阶段 1–3 并满足外部试用条件后，开展成年用户手动试用。验收只使用实际运行、用户纠正、反馈、退出和删除请求形成的授权证据。阶段交付物、验收结果和限制以简洁日志记录于[开发进度日志](开发进度日志.md)，不另建验收报告。

验收关注：端到端完成与失败、事实和推断可追溯性、无依据断言、必要澄清、安全路由、隐私告知、授权撤回、删除完成度和用户反馈。所有结论须标注证据范围；无证据保持“未验证”。

## 阶段 5：价值、付费与方向决策

在阶段 4 完成后，若需要开展价值或付费验证，单独记录样本来源、测试条件、实际付款或预售事实及限制。不得用意愿、满意度或市场调研数字替代付款证据。结论记录于[开发进度日志](开发进度日志.md)。
