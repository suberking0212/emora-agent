## 执行原则

- 本路线首阶段验证面向个人的情感困境分析与复盘 Agent。学生/开发者是首轮测试样本来源，不据此认定为长期目标客群，也不把本项目当前开发目录标签解释为面向企业采购的 B2B 产品。
- 使用成熟开源 Harness 承担工作流编排；本项目聚焦分析契约、权限、对话控制与安全评估，不自行实现 Harness 引擎。每个阶段以用户任务、可验证产物和验收证据推进。
- 用成熟开源解决明确问题；狗头军师用于领域工作流参考，OpenClaw 只可作为内部原型对照，均不是产品运行依赖。
- 对外收集个人经历、聊天片段或私有材料前，必须有明确用途、权限隔离、保留和删除机制。
- 每阶段完成后在 [开发进度日志](开发进度日志.md) 记录结果与未完成项。

## 阶段 0：范围冻结与评测准备

### 任务

- 按两份 PRD 冻结首轮范围，形成需求追踪与验收表；公开证据仅在有实际来源时登记，不把假设写成已验证事实。
- 定义输入、证据、分析、匿名身份、单独授权和安全路由契约，以及数据清单。产品名暂未确定。
- 编制合成人工标注案例和 rubric，覆盖正常分析、材料不足、纠错、OCR 错误、高风险、拒绝授权与删除；冻结阶段 1 的评分规则、技术/质量通过与阻断门槛，不用待定的商业阈值代替开发验收。
- 确认 LangGraph 与 provider 接口方向；允许一次性技术探针，但不要求完整 CLI，也不将探针算作阶段 1 验收。

### 验收与出口

- 范围、PRD 对应关系、阶段依赖、评分规则和数据边界均可审阅；缺失证据明确标记待验证。
- 每个 P0 需求有设计落点、负责阶段和验收案例；通过后进入阶段 1 CLI 实现。

## 阶段 1：CLI 核心闭环与架构可用性验证

### 任务

- 先建立 Python 核心包与 Typer CLI，共享 Pydantic 数据契约；CLI 是第一条可运行产品流程，不先建设 Web/API。
- 将输入层实现为多模态 `InputProvider`：统一文本、图片 OCR 和音频 ASR 的输入契约；将 `SpeechProvider` 作为 TTS 输出契约，供后续 Web 复用。
- 首轮 CLI 必须跑通一条真实非文本输入链路。默认验收链路为“本地图片文件 → OCR provider → 用户可修正的转写文本 → 情感分析 → 结构化结果”；不得以 mock、空接口或手填 OCR 结果代替。音频 ASR 与 TTS 同时纳入 provider 设计和合成案例，但不要求本阶段同时验证全部语音能力。
- 在 CLI 中接入经阶段 0/1 初始化复核并锁定的 LangGraph Python 版本，当前 `1.2.15` 仅为既有候选基线；实现有限节点的情境理解、必要澄清、复盘分析、优化建议和安全检查；使用独立本地 checkpoint 验证进程重启后暂停状态恢复，不以其代替业务结果。
- 实现 SQLite AnalysisRepository，保存输入与结果版本并回读；本地合成主体的归属校验与业务存储同 checkpoint 分开。
- 通过合成情境端到端验证 LangGraph、ModelProvider、分析 schema、安全检查和恢复逻辑是否能组成可用架构；只保留能改善理解、建议质量或可靠性的组件。
- 定义统一的结构化运行事件（如 session、step、model、duration、status、error、version）；CLI 提供人可读结果，并可输出脱敏 JSONL 事件流，作为后续 Web 后端日志的共同格式。
- 运行日志记录步骤状态、耗时、版本、错误码和验证结果；默认不写入原始情感经历、完整 prompt 或敏感第三方材料。
- 不做自主工具循环或 Agent 群。Langfuse 可在 CLI 核心跑通后评估；Temporal/AgentLedger 只有在实际能力缺口成立后另行评估。

### 验收标准

- Typer CLI 能对合成情境独立运行端到端流程，输出通过 schema 的分析、优化建议、不确定项和风险标记；此阶段不依赖 Web/API。
- 至少一份合成或明确获准的图片输入经真实 OCR provider 转为可检查转写，用户/测试脚本可修正转写后进入同一分析工作流；日志记录输入类型、provider、版本、识别状态、修正状态、耗时和错误码，但不记录原始图片或转写全文。
- 输入契约能表达 `text`、`image`、`audio` 三类来源及其确认状态；TTS 契约只接收通过质量与安全检查的结果文本。OCR、ASR 或 TTS 失败均不能使未验证内容进入分析或替代文本结果。
- CLI 日志/事件能追踪输入摘要（脱敏）、工作流步骤、模型、提示、LangGraph、图定义、规则版本、耗时、状态和错误码。
- 用户补充关键背景后可在同一会话继续；验证所选 checkpoint 能保存并恢复必要状态，记录其边界和失败行为。
- CLI 的人可读结果与 JSONL 事件输出职责清楚；事件中不含原始敏感输入或完整 prompt。
- 只有必要时才提问；事实、用户感受和模型推断明确区分，不编造输入中不存在的原话或经历。
- 结果先通过 CLI 的业务契约与 schema 校验；失败时返回结构化错误且不得报告成功。
- “节点/模型调用成功”或 Trace 显示无错误不作为结果正确的证据；将结果保存后读回确认，并用独立 rubric 评估合成/获准案例。评测无法判断时标记未知，不计为通过。
- 校验失败、超时或 Provider 错误时有限重试/安全失败，不输出未校验产物。

## 阶段 2：会话持久化、参考知识与 CLI 评测

### 任务

- 在 CLI 闭环和架构评审通过后，以同一 Repository 契约迁移 PostgreSQL，建立匿名主体、analysis_session、输入/结果版本、授权和反馈模型；保存 LangGraph thread ID 映射；不将 checkpoint 当作业务结果。
- 将原始图片/音频、OCR/ASR 转写、用户修正版本和 TTS 音频作为会话数据及派生数据纳入授权、保留与删除模型；默认不进入长期记忆、训练或共享检索。
- 将通用审核参考资料与单次会话材料分开；用户的情感经历默认不进入长期记忆或共享检索库。
- 仅当外部知识检索经评测证明能提升建议质量时，才实现文档解析、分片与检索。
- 实现会话归属授权、来源许可状态过滤、单独改进同意及撤回、用户数据删除；覆盖在途任务、迟到写回和派生副本。
- 以小型人工标注问题集比较领域提示/审核知识对理解准确性、建议质量和安全性的作用；只有检索评测有增益时再比较关键词、向量和混合检索。

### 验收标准

- 自动化负向用例证明用户 A 无法通过 Repository/CLI、已启用的检索或 thread ID 访问用户 B 的会话和资料。
- 若启用知识检索，每个返回片段有来源和授权信息，且不把相似度当成事实置信度。
- 对检索能力做人工评估，确认其改善分析质量后再纳入首轮工作流。
- 删除会话后，其输入、分析结果、缓存和派生数据均按策略删除或失效。
- 多模态输入及派生数据可按会话分别查询与删除；删除演练覆盖原始文件、OCR/ASR 转写、TTS 音频和缓存。
- 未证明有检索需要前，不建设通用客户内容库或引入独立向量数据库。
- CLI 能调用持久化服务并按统一事件 schema 输出日志；会话结果与 LangGraph checkpoint 可分别查询、删除和恢复。

## 阶段 3：复用 CLI 核心开发 Web UI

### 任务

- 基于 CLI 阶段已验证的 Python 领域核心与数据契约实现 FastAPI；API 调用同一分析服务，不复制一套 Web 专用 Agent 工作流。
- 实现免注册匿名 Cookie 与服务端归属校验；首页用途/年龄/数据告知、改进授权默认关闭且可撤回、复制/下载总结。
- 实现 Next.js 个人用户体验：自然语言描述、情境补充、分析建议对话、可回看的复盘总结、反馈/删除。
- 实现文本与图片输入、识别确认/修正。ASR/TTS 为 P1，本轮计划在本阶段交付；若延期，必须先在需求追踪表记录原因、替代流程和首轮范围变更，禁止静默漏项。启用时 TTS 仅由用户主动触发。
- Web 后端与 CLI 使用同一结构化事件 schema 和日志脱敏规则；Web 请求日志可关联 session/request ID、步骤、耗时、状态、错误和模型/提示/规则版本，并保持 CLI JSONL 可复用回放。
- 模型密钥不进入浏览器；敏感情感材料不得通过浏览器控制台、服务端普通日志或观测平台明文记录。
- Web 端能清楚标识 OCR/ASR 识别内容与用户修正内容；非文本输入或 TTS 服务失败时提供文本回退，且不丢失已确认的会话内容。
- 加入分析质量与安全检查：事实/解释区分、不确定性、对用户自身行为的平衡分析、建议可执行性、敏感/诊断化表达和操纵性建议。
- 对显著改变建议的关键信息才追问；避免固定长问卷、重复追问和诊疗式盘问。
- 先在本地/受控环境运行，再确定外部测试部署与供应商数据流。

### 验收标准

- 测试者能自然描述困境，获得上下文相关的分析和具体优化建议，并能纠正 Agent 对事实的理解。
- 必要澄清问题简短且与建议相关；测试反馈未显示流程退化为机械问答。
- 匿名凭证有效/过期/丢失、CSRF 和跨用户读写/下载/恢复/删除均有测试；API 不凭 session/thread ID 授权。
- 拒绝改进授权仍可完成分析；拒绝的数据不进入评测集；撤回后停止使用并删除可控改进副本。
- 模型输出未经 schema、建议质量和风险检查不交付给用户，SSE 不传未校验正文。
- 对话中的用户纠正、建议反馈、拒绝和总结状态可追踪；不把建议包装为专业诊断或确定结论。
- 日志不含原始情感经历、聊天内容、密钥或完整提示上下文。
- 同一合成测试输入通过 CLI 与 Web API 执行时，核心分析行为和关键事件语义一致；日志均可用于定位失败步骤。

## 阶段 4：学生/开发者首轮封闭测试

### 任务

- 邀请成年学生/开发者测试者体验个人情感困境分析；说明数据用途、风险边界与删除方式，允许使用虚构/脱敏情境完成部分可用性走查。
- 观察描述困境、理解分析、必要澄清、建议采纳/拒绝和总结回看过程；记录用户指出的具体帮助、错误、遗漏、迎合、责备和过度追问。
- 区分有近期相关困境的参与者与仅对 AI 感兴趣的参与者；记录招募来源和样本限制，不将结果外推为整体用户需求。
- 收集明确授权的反馈；未经授权的个人会话材料不进入共享评测集。

### 验收标准

- 有可审计的样本来源、用户授权、测试过程与脱敏反馈记录。
- 形成首轮复盘：理解准确性、建议具体性/可执行性、追问体验、用户纠错、风险问题和样本局限。
- 至少记录是否出现后续复用/行动反馈；不将礼貌性正面评价等同于产品价值。
- 已演练匿名主体的会话数据访问、授权撤回和资料删除。

## 阶段 5：价值、付费与方向决策

### 任务

- 预先设定个人用户服务交付、价格/实验方式、招募样本、成功和停止标准。
- 在首轮质量和价值信号复盘后，决定是否测试个人用户付费；若开展，进行清楚的价格与交付报价，区分“愿意聊”“愿意试用”和“实际付费”。
- 计算单次分析的模型、存储和支持成本；记录人工复核投入。
- 决定是否继续该个人情感分析方向、调整测试对象/场景或暂停；首轮学生/开发者样本不能证明长期目标用户或付费需求。

### 验收标准

- 若开展付费实验，须有真实报价与参与者反应记录；若不开展，记录原因和决策依据，不虚构购买记录或用户评价。
- 已开展的付费实验能回答具体假设，或说明样本/渠道不足以判断；未开展明确标记未验证。
- 输出继续验证、调整 ICP/任务或暂停投入的决策备忘录，附证据、不确定性与下一步。

## 组件选型顺序与升级门槛

1. 首轮采用 LangGraph Python，既有 `1.2.15` 为待复核候选基线；阶段 1 复核可用性及兼容性后锁定 LangGraph 与本地 checkpointer，版本变化同步工程设计和验收记录；阶段 2 再锁定兼容 PostgreSQL checkpointer 依赖，不复制上游源码。
2. Langfuse 优先评估 trace、成本与离线评测；默认脱敏且不收集敏感原文。
3. OpenTelemetry 作为未来跨组件 trace context 标准候选；首轮单体部署可先不引入 Collector。
4. Temporal 仅在真实任务证明需要跨服务长时间等待/分布式恢复且 LangGraph/当前部署无法可靠满足时评估。
5. AgentLedger 作为可靠性设计比较对象，先审查代码、测试、发布和恢复语义，不默认作为第二层 Harness。

依赖升级前核对接口/状态兼容、checkpoint 恢复、用户数据删除、评测结果、成本/延迟，并保留回滚 lockfile/制品；禁止生产自动追随最新版。

## OpenClaw 对照门槛

如果内部团队已有 OpenClaw 环境，可用合成情境对比相同情感分析任务，评估上下文理解、建议质量、隔离能力、部署维护成本和用户体验。对照仅用于决策；除非能通过用户/会话隔离、来源溯源、数据生命周期及安全评估，不用于外部测试者真实材料。

## 跨阶段验收场景

- 阶段 1：文本/真实 OCR 确认、引用定位、先交付已校验初步分析再暂停、澄清跳过/上限、进程重启恢复、完成后纠错新 run、重复恢复幂等、旧任务不得覆盖新输入、provider 失败和保存失败。校验每项解释/建议的证据关联，引用必须与对应版本片段一致；未知不强填证据。
- 阶段 1：初次与补充输入含自伤/暴力/操纵或风险不确定时，均阻断普通建议；前置、二次及输出检查的路由与图一致。
- 阶段 2：SQLite/PG 仓储契约一致；两个合成主体隔离；拒绝/撤回改进授权；删除覆盖 checkpoint/原件/派生文件/在途任务，失败不报完成。
- 阶段 3：免注册完整流程、Cookie 失效/丢失、CSRF、API 越权、文件下载、复制总结、拒绝同意不影响服务、纠错后旧总结/TTS 失效。
- 阶段 4 招募前：确定样本/质量门槛、成年人确认及误收处理、实际期限、供应商数据流和危机处置联系人/资源，逐项记录证据，不以文档完成代替运行验证。

## 发布前共同门槛

- 模型、OCR、ASR、TTS、文件服务商的数据留存、训练和删除政策已核实并告知用户。
- 用户/会话隔离、私有文件访问、删除和授权撤回通过实际演练。
- 对情感、心理健康、诊断治疗、危险关系和未成年人内容建立审校边界。
- 对外测试前完成大陆适用法规与知识内容授权评估。
- 未满足上述门槛前，只用合成或明确获准的资料进行内部演示。
