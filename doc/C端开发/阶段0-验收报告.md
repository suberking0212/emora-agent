# 阶段 0 验收报告

日期：2026-10-16  
结论：**不通过，退回补齐准备材料**

## 对照标准

阶段 0 出口要求来自《阶段任务与验收标准》：

1. 范围、PRD 关系、阶段依赖、评分规则和数据边界可审阅，并明确缺失证据。
2. 每个 P0 需求有设计落点、负责阶段和验收案例，之后才能进入阶段 1 CLI。

## 已核验通过的部分

- `doc/README.md` 作为文档入口，能定位两份 C 端 PRD、工程设计、阶段计划、技术债务和进度日志。
- 用户端、流程和技术模块与两份 C 端 PRD及工程设计的当前口径一致：个人用户情感困境分析，CLI 优先，网页后续。
- `evals/cases/stage0_synthetic_cases.json` 可解析，包含 8 个唯一案例，覆盖正常分析、材料不足、纠正、OCR、高风险、胁迫、操纵、授权与删除。
- `evals/rubrics/stage0_analysis_rubric.md` 已定义评分维度、双人评分和阻断门。
- `doc/C端开发/阶段0-数据清单与决策记录.md` 已列出输入、派生数据、结果、checkpoint、日志、授权和待确认的供应商边界。
- P0/约束需求已有设计落点、负责阶段和案例映射草案，见 `evals/rubrics/stage0_acceptance_matrix.md`。

## 不通过原因

1. **验收案例不完整。** 矩阵中的 `AC-*` 大多只有名称，没有前置条件、操作步骤、预期状态/结果、失败判定和证据路径，不能算可执行验收案例。
2. **需求覆盖仍有缺口。** 8 个 S0 案例没有覆盖首页、文本编辑/清空、反馈、主体隔离、年龄误收、删除失败重试等 P0/约束行为；这些只写成未来占位。
3. **阶段 1 技术门槛未完整冻结。** Rubric 没有把 CLI/Pydantic、结构化结果校验、SQLite 保存读回、checkpoint 重启恢复、幂等恢复、provider 失败和旧任务不得覆盖等技术场景纳入逐例评分与通过门。
4. **契约表述存在冲突。** 数据清单将用户纠正概括为“新输入版本和新 run”，而工程设计区分“暂停澄清可恢复原 run”和“已完成后纠正创建新 run”；需按工程设计补充条件化规则。
5. **没有实际人工评分证据。** 这不要求在阶段 0 伪造模型结果，但必须明确阶段 0 产物是“案例/rubric 已冻结、评分待阶段 1 回放”，不能把静态文件创建写成验收通过。

## 补齐条件

- 为每个 `AC-*` 编写前置条件、输入、操作、预期输出/状态、失败判定和证据文件位置。
- 增加覆盖首页、文本输入、反馈、主体隔离、年龄限制、删除失败/重试以及 CLI 技术可靠性的合成或流程案例。
- 将阶段 1 验收门槛加入 rubric：schema 失败不成功、保存读回、重启恢复、幂等、provider 失败安全失败、旧任务不可覆盖。
- 修正输入版本/run 规则，分别描述澄清恢复和完成后纠正。
- 重新运行阶段 0 文档验收，只有以上材料可审阅后才允许把阶段 0 标记为通过并进入阶段 1。

## 证据边界

当前没有业务代码、CLI、provider、Repository 或 Web。任何运行质量、安全、删除、越权或依赖兼容性结论均待后续实现和测试，不在本报告中推断。
