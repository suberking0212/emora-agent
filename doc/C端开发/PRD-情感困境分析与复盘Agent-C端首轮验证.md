## 1. 决策摘要

本阶段验证的是面向个人的情感困境分析与复盘 Agent。学生/开发者群体是获取第一轮真实使用数据的首批测试样本，**不因此等同于长期目标客群，也不代表产品是面向企业采购的 B2B 服务**。本目录中的“C 端开发”是项目当前开发工作区的分类。

- **首轮测试对象：**可触达的成年学生/开发者；招募时优先考虑近期确有恋爱或亲密关系困境、愿意体验并反馈的人。样本用于发现体验、质量、信任和价值问题，不能代表总体市场。
- **核心任务：**用户用自然语言讲述自己的感情经历、矛盾和疑问，Agent 理解上下文，帮助用户分析“发生了什么、自己可能做错/遗漏了什么、有哪些其他解释、可以怎样处理”，并给出具体、尊重边界的优化建议。
- **产品交互：**LLM 作为分析与决策核心，先基于现有输入尽可能形成有用判断，再用少量、必要的追问澄清会显著改变建议的信息。对话由 Agent 自然引导；不采用固定长问卷、连续盘问或诊疗式逐题问答。
- **输入与语音能力：**输入层支持文本、聊天截图 OCR 和语音讲述 ASR；非文本先转为用户可检查/修正的文本后才进入分析。TTS 可按用户请求播报已校验的结果，不替代文本输出。
- **首轮价值假设：**相较用户直接向通用 LLM 提问，针对情感沟通、关系互动和相关心理学知识设计的 Agent，能更准确理解问题、提供更有依据且可执行的建议，并清楚说明判断边界。
- **证据状态：**首轮测试对象与产品方向来自项目决策；具体需求、报告质量、相较通用 LLM 的增量价值、复用和付费均未验证。首轮测试首先获取真实使用数据，不据此直接宣称市场成立。

## 2. 用户问题与核心任务

用户可能带着一段经历、一组矛盾或一个直接问题进入，例如“我是不是做错了？”“为什么我们总是吵到这里？”“我接下来怎么处理？”。用户通常需要的不只是情绪标签或聊天内容复述，而是一个能综合理解语境、分析自身行为与互动模式、给出下一步选项的决策辅助工具。

### 核心 JTBD

> 当我陷入一段具体的情感困境时，我希望把经历和矛盾讲清楚后，得到一个理解上下文、能分析多种可能原因、也愿意指出我自身可调整之处的建议，帮助我决定接下来怎么做，而不是只获得安慰、武断评判或一连串问题。

产品应能指出用户可能的误区或责任，但要基于用户提供的事实和推理说明，避免迎合用户或为了“犀利”而责备用户。涉及第三方动机时给出可能性，不伪装成确定事实。

## 3. MVP 目标与非目标

### 目标

1. 让首轮测试者能以自然语言描述困境，并完成一次有清晰价值感的分析与复盘。
2. 验证 Agent 能否在有限澄清的前提下理解上下文、回应用户真正的问题，并提供具体、可执行的优化建议。
3. 评估用户是否认为分析有依据、是否发现盲点、是否会据此采取或调整行动；收集具体纠错和不适用反馈。
4. 获取首轮真实使用数据，为继续、调整或停止方向提供依据；区分学生/开发者招募样本与未来待识别的目标客群。
5. 在接收真实个人经历前完成清晰的数据告知、最小收集、访问控制、保留和删除设计。

### 非目标

- 专业情感博主内容创作工具、咨询师工作台或面向机构的服务流程；这些不是本阶段目标。
- 心理治疗、精神障碍诊断、婚姻治疗、法律意见或专业咨询替代。
- 以固定量表或大量连续问题完成“诊疗”；也不为追求聊天时长而无目的追问。
- 断言另一方真实想法、诊断人格/依恋类型、保证挽回或预测关系结局。
- 操控、PUA、跟踪、监视、报复或诱导第三方作决定。
- 首轮即建设复杂长期记忆、社交网络、多 Agent 协商、自动联系第三方或规模化获客系统。

## 4. 首轮体验与对话原则

1. 用户可直接讲述经历，也可提出明确问题；不要求先完成长问卷。界面只提示用户提供有助于分析的背景，并允许跳过非必要信息。
2. Agent 先解析用户目标、关键事件、双方行为、用户感受和已有解释；遇到材料不完整时，仍先给出当前可做的分析，并标明不确定部分。
3. 只有当缺失信息会实质改变判断或建议时才追问。每轮问题应简短、相关、可回答；不重复询问已给出的信息，不强迫用户按预设流程逐题作答。
4. Agent 可主动组织对话，例如先给初步分析和建议，再邀请用户纠正关键事实或补充一个决定性背景。用户补充后应更新判断，而不是机械重复报告。
5. 回应应优先解决用户的困惑：包括可能发生的互动循环、用户自身可以调整之处、其他合理解释、建议及其适用条件。不给空泛鸡汤，也不把“指出用户的问题”误作责备。
6. 对话结束时，用户应能带走清楚的总结与下一步选择；不通过制造依赖、悬念或焦虑延长会话。

## 5. 分析输出

可用自然对话呈现，不强制每轮输出固定模板；在适合总结时包含：

- **问题理解：**用简洁语言确认用户真正想弄明白或决定的事情。
- **已知事实与用户感受：**区分用户明确叙述的事件、感受和对事件的解释。
- **互动与矛盾分析：**指出可能重复出现的互动模式，分析支持依据与不确定处。
- **多种可能解释：**材料足够时呈现合理替代解释，避免只站队或读心；说明哪些信息会改变判断。
- **对用户自身的反馈：**温和但诚实地指出可能的行为影响、未表达需求、边界或认知盲点，并说明推理依据。
- **优化建议：**给出具体、可选择的处理方式、沟通表达或观察步骤，并说明各自适用情境和潜在代价。
- **边界说明：**在不确定处坦诚说明，绝不将推断包装为诊断、事实或保证。

## 6. 首轮验证指标

- 开始体验、完成一次有效分析、主动补充信息、提前退出的比例与原因；
- 用户是否认为 Agent 理解了其实际问题，而非只复述输入或套用通用安慰；
- 建议的具体性、可执行性、对用户自身行为的分析质量，以及用户指出的无依据/迎合/责备/遗漏；
- Agent 追问次数、用户对追问必要性和对话自然度的反馈，检查是否滑向过度问答；
- 用户是否采取、考虑或拒绝建议及其理由；是否带着新情境再次使用；
- 用户对比通用 LLM 的具体体验差异；
- 隐私顾虑、敏感材料提交意愿、删除请求与安全事件；
- 图片 OCR、语音 ASR 的识别失败与用户修正比例，以及非文本输入是否让用户更容易完整讲述问题；
- TTS 是否被主动使用、是否影响理解或隐私顾虑；
- 如进入后续商业验证，再测试明确交付和真实价格下的付款行为。首轮满意度或“觉得很准”不等同于付费证据。

## 7. 风险与隐私边界

首轮仅招募 18 岁及以上成年人，招募前确定年龄确认与误收处理流程。关系经历、聊天记录可能包含本人和第三方的敏感信息；只收集分析所需的最少信息，提示脱敏，明确处理目的、保存期限、访问范围与删除方式。产品改进授权默认关闭、单独选择、可撤回，拒绝不影响本次服务；该授权只涵盖已告知的人工质量审阅/评测，不自动涵盖模型训练或公开展示。未经相应用途的明确授权，材料不得进入训练、共享案例库或跨用户检索。高风险情境（暴力、胁迫、自伤、自杀、即时安全威胁）须触发相应安全回应，不能按普通关系优化继续给建议，也不能暗示提供实时人工危机服务。

外部测试前，完成模型/存储服务商数据政策、数据流、授权、保留删除、访问控制及适用合规评估。未完成前仅使用合成材料开展内部技术验证。

## 8. 首轮交付与范围

首轮测试产品的核心交付是**一段有上下文的情感分析与建议对话，以及用户可回看的复盘总结**。重点放在优化建议和决策支持，避免将产品体验收窄为内容生成或固定格式长报告。

首轮最低流程：用户讲述困境 → 非文本经 OCR/ASR 转写并由用户确认 → 安全筛查与分析 → 先交付通过检查的有限分析，必要时附可跳过的简短澄清 → 补充或纠正后重新筛查并更新判断 → 生成可带走的总结与反馈入口。CLI 是阶段 1/2 的内部验证入口，中文网页是阶段 4 外部测试入口。文本、图片为 P0；ASR/TTS 为 P1，计划阶段 3 交付，延期须在阶段计划的需求追踪表登记原因、文本替代流程及范围变更，不能静默省略。用户主动触发 TTS，且只能播放当前已校验结果。

## 9. 与 C 端 PRD 及后续商业假设的关系

本阶段在 C 端开发目录内推进，产品服务对象是个人用户，与 C 端产品设计 PRD 的个人沟通复盘方向一致。该 PRD 聚焦首轮测试策略和核心价值；C 端产品设计 PRD 维护较完整的产品体验、隐私、安全和发布细节。两份文件共享“理解经历、分析矛盾、提供优化建议”的产品定位。

功能、体验、隐私和安全边界以产品体验 PRD 为准；本文件维护首轮样本、假设与实验决策。工程设计不得自行改变产品要求，阶段计划不得以延期隐式删除需求；冲突须在两份 PRD 和[阶段计划的需求追踪表](阶段任务与验收标准.md)同步记录范围决策后解决。文档完成不代表功能实现或需求验证。

本文件第 11 节保留“免费个性化洞察 → 付费深入分析”的待验证商业假设。它是后续实验方向，不代表首轮测试已经包含付费墙或证明商业模式成立。首轮先看真实使用价值和交互质量，再决定是否开展价格实验。

## 10. 关键假设与决策门

| 假设 | 支持信号 | 反证/需调整信号 | 验证方式 |
|---|---|---|---|
| 自然语言讲述比长问卷更适合首轮体验 | 用户能直接开始，较少因表单退出 | 用户难以组织经历且无引导时分析质量差 | 观察输入、完成率与访谈 |
| 少量澄清可改善建议而不过度问答 | 关键缺失被澄清，用户认为问题相关 | 反复问已知信息、用户感到被盘问 | 记录追问与用户评价 |
| 情感专长 Agent 能比通用 LLM 更好理解和分析 | 用户指出具体盲点、依据和建议差异 | 输出仍泛化、迎合、臆测或建议不可执行 | 同一匿名合成/授权案例进行对比评估 |
| 优化建议是用户最核心的价值 | 用户能说出下一步选择或行动变化 | 用户只觉得被安慰/有趣但无法用于决策 | 任务后反馈与后续回访 |
| 首轮学生/开发者样本能帮助改进体验 | 获得多样具体反馈，发现可复现问题 | 样本只追求新奇或无相关经历 | 记录筛选条件、背景和样本局限 |
| 有价值的免费体验可能转成实际付款 | 对明确报价和交付有实际购买行为 | 只口头感兴趣或仅接受免费试用 | 后续独立付费实验 |

阶段结论须将“测试样本表现”“产品质量”“目标客群判断”“商业验证”分开记录，不得从首轮学生/开发者反馈直接推断所有个人用户或企业客户的需求。

## 11. C 端情感分析的商业模式假设（待独立验证）

**核心假设：**用户遇到具体情感困境时，愿意先体验免费的、基于其实际描述的个性化分析；若体验提供具体、可信且有帮助的洞察，用户可能为更深入的证据分析、决策支持和行动方案付费。尚无真实转化数据支持该假设。

候选路径为：免费入口描述困境；免费体验给出核心矛盾、可核对的互动观察、初步解释及其边界；付费交付更完整的多种解释、证据分析、用户可调整之处和行动方案；关系变化后可复盘。免费部分本身应有帮助，不以截断句子、隐藏秘密或制造焦虑推动付费。

首轮可后续测试 ¥9.9、¥19.9、¥39.9 等实验价格，但价格、样本和交付须重新设计并记录；这些只是实验点，不是已验证定价。观察真实付款、交付完成、复用和服务成本，不把口头意愿或“觉得说得准”单独当作商业验证。隐私和关系分析边界依第 7 节执行。
